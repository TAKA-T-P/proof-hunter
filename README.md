# 証明ハンター Ver.1.2

**図形に隠された3つの根拠を探し出せ！**

## 1. アプリ概要

中学数学の「三角形の合同の証明」と「平行四辺形・ひし形・長方形になることの証明」を、ゲーム感覚で練習できるWebアプリ。
インストール・ログイン不要。PC・スマートフォン・タブレットのブラウザで動作する静的Webアプリ（ビルド不要、`file://` でも起動できる）。

Ver.0.3 で、これまでのゲーム（**ハンターモード**）に加えて **証明パズルモード** を追加し、
Ver.0.4 で証明パズルを **3段階の解答レベル**（おてがる → スタンダード → チャレンジ：「えらぶ」→「くみたてる」→「自分で思い出す」）にした。
Ver.0.5 で、結論が三角形の合同ではなく **辺・角の等しさ**（例：AC＝BD、∠ABC＝∠CDA）の問題を、両モード・3レベルに追加した（STAGE 6）。
「どの三角形を合同にする？」→「3つの根拠」→「合同条件」→「合同だから対応する辺・角が等しい」の順に考える。
Ver.0.6 で、第3のモード **段位認定**（120秒でミニ問題を次々に解き、10級〜皆伝の21段階で認定）を追加した。
Ver.0.7 で **多段階証明**（STAGE 7）に対応した。定理（二等辺三角形・正三角形の性質）を1ステップで使い、角の和・差の式を2つ比べて新しい等式を導き（三段論法）、導いた事実を合同の根拠に再利用する。
Ver.0.8 で **直角三角形の合同条件**（斜辺と1つの鋭角・斜辺と他の1辺）を両モード・3レベルに追加し（STAGE 8）、段位認定を **基本の合同証明・総合証明の2コース** にした。
Ver.0.9 で **平行四辺形**（4つの性質・5つの成立条件・平行を導く推論・四角形が平行四辺形になることの証明）を両モード・3レベルに追加し（STAGE 9「平行四辺形を利用せよ！」・STAGE 10「平行四辺形を証明せよ！」）、段位認定の総合証明に平行四辺形のミニ問題を加えた。「三角形の合同を示す」から「四角形の性質を証明する」へ（4-11）。STAGE 6 には、合同から錯角の等しさを導いて「錯角が等しいから平行」を示す問題（p35）を加えた。
Ver.1.0 で **特別な平行四辺形**（ひし形・長方形・正方形の分類・成立条件・包含関係）を追加し、STAGE 11「特別な平行四辺形」（p43〜p47。ひし形と直角三角形の合同、ひし形・長方形になることの証明、長方形・ひし形の対角線の性質を三角形の合同で証明）を両モード・3レベルで遊べるようにした。段位認定の総合証明に、条件から四角形の名前を答える **「四角形の分類」** のミニ問題を加えた（4-12）。（はじめの Ver.1.0 の6問のうち、証明方法が複数あり複雑な3問（角の二等分線・中点と合同・対角線と合同）は削除した）
Ver.1.1 で、第4のモード **証明の間違い探し**（証明文に隠された間違いを1か所見つける。30問）を追加した（4-13）。
Ver.1.2 で、証明の間違い探しに **ランダム5問チャレンジ**（基本の合同証明・総合証明の2コース、100点満点）を追加し、既存30問に **誤りのバリエーション**（同じ証明で、間違いの場所・種類を変えた版。全119通り）を用意した（4-14）。

- **ハンターモード**：図をタップして等しい辺・角とその理由を見つけ、3つの根拠を集めて合同条件を選ぶ（「根拠を見つける」）。
- **証明パズルモード**：等式・理由・合同条件のカードをタップで空欄に入れ、証明文を完成させる（「証明を組み立てる」）。
- **段位認定モード**：120秒で、証明の一部分を取り出したミニ問題に次々に答え、正解数とミス数から段位を認定する（「学んだ知識を素早く正確に使う」）。
- **証明の間違い探し**（Ver.1.1）：間違いを1か所ふくむ証明文を読み、間違っている行をタップする（「証明を読む → 間違いを見抜く → 正しい証明を確認する」）。Ver.1.2：じっくり練習（30問）と、ランダム5問チャレンジ（2コース）。同じ問題でも開くたびに間違いの場所が変わる。

ハンター・パズルは同じ50問・10ステージを使い、記録と評価はモードごと（パズルはさらに解答レベルごと）に別々に保存される。段位認定のミニ問題も、この50問の正解データと推論ルールから自動で作る（問題文や正解を別に書き写さない）。証明全文の自由記述は行わない（紙のノートでの練習を想定）。

## 2. 開発目的

- 証明を書く前段階の思考（どこが等しいか・なぜ等しいか・どの合同条件か）を、短いテンポで繰り返し練習できるようにする。
- 証明文の構成（等式と理由の対応、3つの根拠と合同条件の関係）を、選択式で無理なく身につけ、定期テストで証明を書く力への橋渡しにする。
- 数学が苦手な生徒でも、証明への心理的ハードルを下げて取り組めるようにする。
- 図形から必要な情報を見つけ、理由を考え、合同条件を判断できる力を育てる（証明文の暗記ではない）。

## 3. 対象学年

- 中学2年生（図形の合同・証明の初学者）
- 中学3年生（証明の復習）
- 証明が苦手な生徒

## 4. 4つのゲームモード

タイトル画面の4枚のカード（ハンター／証明パズル／証明の間違い探し／段位認定の順）からモードを選ぶ（スマホは縦に並べ、PC は2列×2段）。説明文は「図をタップして、3つの根拠を探せ！」「カードを選んで、証明を完成させよう！」「証明文に隠されたミスを見抜け！」「120秒で何問解けるかチャレンジ！」。間違い探しのカードは緑系（ティール）。段位認定のカードはゴールド系（最高段位は段位認定のトップ画面で表示し、タイトル画面には出さない）。「つづきから」は、最後にプレイしたモードと問題を再開する（例：「証明パズル・問題04」）。

### 4-1. ハンターモードの遊び方

1. ステージを選び、問題を選ぶ（どのステージ・どの問題からでも挑戦できる）。
2. 「辺選択」なら **辺** を、「角選択」なら **角（角の内側）** を2つタップ → 等式の候補（例：`AB＝CB`）が表示される。
   辺選択では辺だけ、角選択では角だけがタップに反応するので、頂点付近でも誤選択しない。
3. **等しい理由** を選び、「根拠を確定」。等式と理由の両方が正しければ根拠スロットに登録される。
   - 共通な辺・共通な角は、同じ辺（角）を2回タップする（`BD＝BD`）。選択中の表示が赤に変わり、3回目のタップで選択解除。
4. 3つの根拠が揃ったら **合同条件** を3択（直角三角形の問題は5択）から選んで「決定」。直角三角形の問題では、根拠の欄が「直角・斜辺・他の1辺（鋭角）」になる（4-9）。
   平行四辺形になることの証明（STAGE 10）は、平行四辺形になるための根拠（2つ。平行は「＝⇔∥」で ∥ に切りかえる）を集めて、5つの成立条件から選ぶ（4-11）。
   ひし形・長方形になることの証明（STAGE 11）は、根拠を集めると「AB＝BC＝CD＝DA」などが表示され、「4つの辺がすべて等しい」「4つの角がすべて等しい」「4つの辺と角がすべて等しい」の3択から成立条件を選ぶ（4-12）。
5. 「証明成功！」→ 完成した証明文と「今回のポイント」を確認する（式・理由をタップすると図の該当部分が光る）。
6. 困ったら「ヒント」（図の右のボタン。3段階）や、図の右の「三角形確認」（対象の三角形と対応する頂点を表示）を使う。印を消すときは「印つけ」の中の「消す」（🧽）を押す（Ver.1.0 で、ツールバーの「消す」をヒントに変え、消すは印つけモードの中に移した）。
7. タイトルバー左上の「◀ 問題」で、そのステージの問題選択画面に戻る（証明パズルも同じ）。
8. タイトルバー右上の「パズル」で、同じ問題の証明パズルへ切りかえられる（「証明パズルモードに切り替えますか？」→ おてがる／スタンダード／チャレンジ／キャンセル。Ver.1.0）。

### 4-2. 証明パズルモードの遊び方

1. パズルのステージ選択画面の上で **解答レベル**（おてがる／スタンダード／チャレンジ）を選ぶ（初期値はおてがる。選んだレベルは保存され、次回も同じ）。
2. 図と仮定・結論を確認する。
3. 証明文の空欄（解答欄）をタップする。画面の下に、その空欄に入るカード（等式／理由／合同条件）だけが出てくる（チャレンジの等式欄では数学キーパッドが出る）。カードをタップすると空欄に入り、カードの領域は隠れる（選択中の空欄は次の空いている空欄へ進む）。
   - 入れたカードは何度でも変えられる（空欄をもう一度タップ → 別のカード）。カードの領域の「×」で何も選ばずに閉じる。
   - 「すべてリセット」は証明文の下にあり、全部の空欄を空にする。
   - カードを入れたり変えたりするだけではミスにならない。
4. すべて埋めたら、証明文の下の「答え合わせ」。まちがえた空欄は赤くなり、理由が表示される。正しく入っているカードは残るので、赤い所だけ直して、もう一度答え合わせする。
5. すべて正しければ「証明パズル完成！」→ 完成した証明全文（式・理由をタップすると図が光る）、今回のポイント、学習のポイントを確認する。
6. 困ったら「ヒント」（3段階。未完成・不正解の部分を優先）。
7. STAGE 6（結論が辺・角の等しさ）の問題では、証明文の最初の「△＿と△＿において」と、最後の「したがって、〜から、結論」も空欄になる（→ 4-6）。
8. 図をタップすると、図が大きく表示されて**印をつけられる**（ハンターモードと同じ：辺の印1〜3本・角の印1〜2本・消す・印をすべて消す）。閉じると、つけた印が問題の図に表示される。印は下書きで、答え合わせには関係しない。

### 4-3. 3つの解答レベル

全50問を3つのレベルすべてで遊べる。★評価・クリア状況・復習はレベルごとに別々。

ただし証明パズルで★★★を取ると、同じ問題の下位の解答レベルも★★★になる（チャレンジで★★★ → おてがる・スタンダードも★★★、スタンダードで★★★ → おてがるも★★★）。結果画面で「〇〇 のこの問題も ★★★ になったよ！」と知らせる。

| レベル | 説明（ボタン） | 画面 | 生徒が答えるもの | 判定 |
|---|---|---|---|---|
| **おてがる**（穴埋め・fill） | 等式を選んで穴埋め！ | 証明文の理由（「仮定より」など）は表示済み。等式と合同条件が空欄 | 各行の等式カード（3つ）＋合同条件 | 等式が、その行に表示された理由で言える根拠か。同じ理由の行どうしなら入れかえてもよい |
| **スタンダード**（組み立て・build） | 等式と理由を組み立てよう！ | 根拠①〜③それぞれに「理由」と「等式」の空欄。最後に合同条件 | 理由カードと等式カードのセット（3組）＋合同条件 | 等式が根拠であること、理由との組み合わせ、重複がないこと。根拠の順番は自由 |
| **チャレンジ**（challenge） | 等式を自分で入力しよう！ | スタンダードと同じ形。**等式カードは出さない** | 理由カード＋**等式を数学キーパッドで入力**（3組）＋合同条件 | スタンダードと同じ。入力した等式は正規化して同じ判定にかける |

どのレベルも、合同条件は「答えた3つの根拠から導かれる条件」と一致するかで判定する。

- プレイ画面のタイトルバーに現在のレベルを表示。タップすると「解答形式を変更すると、今の解答内容はリセットされます。変更しますか？」と確認したうえで、新しいレベルで最初からやり直す（ミス・ヒント・印もリセット。保存ずみの最高評価は変わらない）。この確認には、ほかの2つのレベルのボタンの下（キャンセルの上）に「ハンターモードに切り替える」があり、同じ問題のハンターモードへ移れる（Ver.1.0。`chooser.js` の選択肢の `wide`）。
- そのレベルの全問をクリアすると、ステージ選択画面と完成画面に案内を表示（自動でレベルは変えない）：「おてがる全問クリア！ 次はスタンダードに挑戦してみよう！」「スタンダード全問クリア！ チャレンジにも挑戦してみよう！」「証明マスターへの道をクリア！ ノートでも証明を書いてみよう！」

### 4-4. チャレンジの数学キーパッド

等式の空欄をタップすると、画面の下にキーパッドが出る（スマホ縦向きは下からのシート、スマホ横向きなど高さの低い画面は画面の下に固定したシート（選んだ空欄がシートの上に見えるようにページが動く）、PCは右側の欄の下）。

```text
┌─────────────────────────────┐
│ [    AB＝C＿    ] [辺⇔角]        │ ← 入力中の式（最初は辺）と、辺の等式⇔角の等式の切りかえ
│                                │    角にすると [ ∠＿＿＿＝∠＿＿＿ ] [辺⇔角]
│  A   B   C   D   O              │ ← その問題の図にある頂点記号だけ
│  ←   消す        決定           │ ← ＝・∠ のボタンはない（入力欄に表示ずみ）
└─────────────────────────────┘
```

- 入力例：辺は（最初から辺の入力欄なので）A → B → C → D → 決定 で `AB＝CD`。角は入力欄の右の「辺⇔角」→ A → B → C → D → E → F → 決定 で `∠ABC＝∠DEF`。＝ と ∠ は入力欄に最初から表示されているので押す必要はなく、左辺を入力しおわると自動で右辺に進む。
- 入力ルール：辺は2文字、角は∠＋3文字。左右は同じ種類。図にない文字は押せない。同じ辺・角の中で同じ文字（AA、∠ABA など）は押せない。不完全な式は「決定」できない。
- 今押せる文字を強調する。←で1文字削除（右辺が空なら＝をまたいで左辺の最後の文字を消す）、「消す」で最初から。←・消す・決定は1行に並ぶ。「辺⇔角」で種類を切りかえると、その欄の入力はリセット（「辺の等式」「角の等式」の2つのボタンは Ver.0.8 で廃止）。段位認定の記号入力も同じキーパッド。
- **三角形の入力**（Ver.0.5、STAGE 6 の「△＿と△＿において」の欄）：入力欄は `△□□□と△□□□`。種類のボタンはなく、頂点記号を6つ押して「決定」（A → B → C → D → E → F で △ABCと△DEF。1つ目を入力しおわると自動で2つ目へ）。同じ三角形の中で同じ文字は押せない。図にない三角形（一直線上の3点、かかれていない辺）や同じ三角形を2つ入力したときは、理由を赤く表示して決定できない。頂点の対応は、入力した2つの三角形の頂点の順番から判定する（文字列の一致ではない）。
- 入力途中の式は空欄ごとに残る（別の空欄に移っても、図を開いて印をつけても消えない。図のウィンドウを閉じるとキーパッドに戻る）。決定すると空欄に入り、キーパッドは隠れて次の空欄へ進む。
- **平行の入力**（Ver.0.9、平行四辺形の根拠の欄）：入力欄は `□□∥□□`。種類の切りかえボタンは「辺⇔角⇔∥」になり、辺 → 角 → ∥ の順に切りかえる（ボタンの表示は、その欄で入力できる種類だけ）。空欄の種類が分かっているので、**最初の入力の種類はその行の根拠に合わせて自動で設定する**（AD∥BC の行は最初から ∥。毎回「等式／平行」を選ばせない）。三角形の合同の部分の等式の欄には平行は入らない。段位認定の「平行な2つの辺は？」も同じ入力。
- キーパッドのボタンは、指が触れた時点（`pointerdown`）で入力する（Ver.1.1。証明パズルのチャレンジ・段位認定の両方）。押すたびにキーパッドを描き直すので、指をはなしたとき（`click`）に受けると、すばやく A→C と押したときに C の入力が届かないことがあった。前の指をはなす前に押した次のキーも受け付ける。Tab で選んで Enter・Space で押すキーボード操作は、これまでどおり。
- PCのキーボード：A〜Z（頂点記号）、Backspace、Enter（決定）、Esc（閉じる）。`=` は押しても押さなくてもよく、`<` は角の等式に、`/`・`|` は平行に切りかえる（平行を入力できる欄だけ）。貼り付けでは `AB∥CD`・`AB//CD`・`AB|CD` を受け付ける。正しい形式の等式なら貼り付けもできる（三角形の欄は `ABC/DEF`・`ABCとDEF`・`ABC,DEF` など）。
- 正規化：小文字→大文字、全角・半角の英字と＝の同一視、空白の除去。数学的な同一性（AB＝CD と CD＝AB、AB と BA、∠ABC と ∠CBA、一直線上の点による角の別名）は既存の `geometry.js`・`validation.js` で判定する。
- **頂点の対応順**：チャレンジでは、根拠として正しい等式でも、2つの三角形の頂点の対応順に合った書き方でなければ正解にしない（`validation.correspondenceOrder`）。左辺を一方の三角形の頂点で読み、対応で移したものが右辺と文字の順番まで一致すればよい。
  - 例（p01 △ABD≡△CBD、A↔C・B↔B・D↔D）：AB＝CB、BA＝BC、CB＝AB は正解。AB＝BC、共通な辺の BD＝DB は「対応順が合っていないよ」。
  - 角は一直線上の別名を三角形の頂点に読みかえて確かめる（p03 で ∠BAC＝∠DCA は正解、∠CAB＝∠DCA は対応順の誤り）。
  - 対応順の誤りはミスに数えない（理由の誤りが同時にあれば、理由の誤りだけミス）。おてがる・スタンダードのカードは正しい対応順で書かれているので影響しない。
- 正誤は「答え合わせ」で判定する（入力中には判定しない）。チャレンジの判定メッセージ：

| 状況 | メッセージ |
|---|---|
| 等式が誤り | その2つが等しいと言えるか、図と仮定を確認しよう。 |
| 理由だけ誤り | 等式は合っているよ！ 理由をもう一度考えてみよう。 |
| 根拠が重複 | 同じ根拠が2回使われているよ！ |
| 結論から導く関係 | それは合同が証明できてから使える関係だよ！ |
| 合同条件が誤り | 3つの根拠と合同条件の関係を確認しよう。 |
| 頂点の対応順が合っていない（例：p01 で AB＝BC） | 対応順が合っていないよ！ 結論 △…≡△… の頂点の順番に合わせて書こう。（**正解にしないが、ミスにも数えない**） |
| 等式が未完成 | （決定できないので空欄のまま。「答え合わせ（あとnか所）」と表示） |

- チャレンジのヒント：1段階目は考え方、2段階目は図の該当部分を光らせる、3段階目は正しい等式を表示（自動では入力しない。自分で入力する）。

### 4-5. 評価（両モード共通）

★★★ ミス0・ヒント0 ／ ★★ ミス2回以内かつヒント1回以内 ／ ★ その他。

- ハンター：誤った等式・理由・合同条件を確定するとミス1回。
- パズル：答え合わせのとき、誤りのある根拠の組・合同条件ごとにミス1回。**同じ誤りのまま答え合わせをくり返してもミスは増えない**（別の誤ったカードに変えると、そのぶん増える）。
- STAGE 6：三角形の誤り（組・対応）、最終結論の等式・理由の誤りも、それぞれミス1回（同じ誤答の再判定では増えない）。

### 4-6. 合同から結論を導く問題（Ver.0.5、STAGE 6）

結論の種類（`conclusionType`）は3つ。p01〜p15 は従来どおり三角形の合同で、手順も変わらない。

| 種類 | ID | 例 | 問題 |
|---|---|---|---|
| 三角形の合同 | `triangleCongruence`（省略時） | △ABC≡△DEF | p01〜p15 |
| 辺の等しさ | `equalSide` | AC＝BD | p17・p18・p19 |
| 角の等しさ | `equalAngle` | ∠ABC＝∠CDA | p16・p20 |

辺・角の等しさの問題は、次の4段階で進む。**合同が成立した時点ではクリアにならず、STEP 4 まで正解して「証明成功！」になる。**

1. **三角形を選ぶ**：「どの2つの三角形を合同にすればよい？」→「△＿と△＿において」を完成させる（証明パズルでは頂点の対応もふくむ。ハンターは入門用のモードなので、2つの三角形を選ぶだけで頂点の対応は答えない）。
2. **3つの根拠**：従来と同じ。最終結論や、まだ証明していない合同から言える関係（対応する辺・角）は根拠に使えない。
3. **合同条件**：正しければ「合同成立！ あと一歩で証明完成！」と表示し、2つの三角形を色分けする。
4. **結論を導く**：結論の2つの辺（角）を選び、理由「合同な図形の対応する辺（角）は等しい」を選ぶ。

**ハンターモードの操作**

- STEP 1 は「△ 三角形の内側をタップ」モードで始まる（辺選択・角選択はできない。印つけはできる）。1つ目の三角形は青、2つ目は黄で表示。選んだ三角形をもう一度タップで解除、3つ目をタップすると2つ目と入れかわる。重なった三角形をタップしたときは「どの三角形を選びますか？」で選ぶ（候補は図にかかれた三角形だけ）。
- 2つ選んだら「決定」（赤）。ハンターは入門用のモードなので、頂点の対応は答えない（正しい組なら、対応は問題データから決まり「三角形確認」ボタンで見られる）。「消す」で選んだ三角形をすべて消す。
- パネルの上に手順（①三角形 ②根拠 ③合同条件 ④結論）を表示する。
- STEP 4 の理由の選択肢：仮定より・問題の理由（対頂角など）・合同な図形の対応する辺より・合同な図形の対応する角より。ボタンは「証明を完成する」。
- 図の右の「三角形確認」ボタンは、STEP 1 の間は「三角形を探すヒント」（正しい三角形は見せず、「結論の辺ACは、どの三角形にふくまれているかな？」などを表示し、結論の辺・角を光らせる）。STEP 1 が正解したあとは、証明する2つの三角形と対応する頂点を表示する。

**証明パズルの3レベル**

| レベル | 三角形（最初） | 根拠・合同条件 | 最終結論（最後） |
|---|---|---|---|
| おてがる | 「△ABDと△CBD」のような三角形の組を3択（ダミーは対応ちがい） | 既存の穴埋め | 理由「合同な図形の対応する辺（角）は等しいから」は表示済み。結論の等式を3択から選ぶ |
| スタンダード | 1つ目の三角形のカード（図の三角形）＋2つ目の三角形のカード（頂点の並び6通り。並びが対応を表す。1つ目と同じ三角形は出さない） | 既存の組み立て | 理由カード（対応する辺／対応する角／仮定）＋結論の等式カード |
| チャレンジ | キーパッドで三角形を入力（△□□□と△□□□） | 既存のチャレンジ | 理由カード＋結論の等式をキーパッドで入力 |

- 合同の行（「…ので、△＿≡△＿」）は、生徒が答えた三角形で表示する（STEP 1 の答えは見せない）。答え合わせのメッセージにも、証明する三角形は書かない。
- 完成した証明は「△AOCと△BODにおいて … ので、△AOC≡△BOD / したがって、/ 合同な図形の対応する辺は等しいから、/ **AC＝BD**」の形。合同は途中の結果として小さめに、最終結論を枠つきで強調する。式・理由・結論をタップすると図が光る。

**判定メッセージ（STAGE 6 の追加分）**

| 状況 | メッセージ | ミス |
|---|---|---|
| 三角形の組は正しいが、頂点の対応がちがう（証明パズルのみ。ハンターでは頂点の対応を答えない） | 三角形は見つけられたね！ 頂点の対応順を確認しよう！ | ○ |
| 三角形の組がちがう | この2つの三角形で、結論を導けるかな？ 対応する辺・角に注目しよう！ | ○ |

| 未完成（ハンター） | （「決定」を押せない。「2つの三角形と、対応する頂点を決めよう」の案内） | × |

**ヒント**（3段階。新しい段階を開いたときだけ回数が増え、★評価に反映。最終段階でも答えは自動で入れない）

- 三角形の選択：①「結論の辺・角は、どの三角形にふくまれているかな？」②「結論で等しいと示したい2つの辺・角を、別々の三角形に見つけよう！」（結論の辺・角を光らせる）③ 合同にする三角形の候補と対応する頂点を表示（自動では確定しない）。
- 最終結論：①「合同な三角形で、対応する辺や角にはどんな性質があるかな？」②「結論の…を、合同な三角形の対応関係で確認しよう！」③「合同な図形の対応する辺（角）は等しい、という性質を使おう！」
- ヒントの対象は、三角形 → 根拠 → 合同条件 → 最終結論 の順（パズルは、まだ正しくない所を優先）。

### 4-7. 段位認定モード（Ver.0.6）

**基本ルール**

- 制限時間は **120秒**（固定）。時間内に解ける問題数は無制限。開始前に「3・2・1・START！」を表示し、STARTと同時に計測を始める。
- 1問の解答箇所は **1つだけ**（テンポを上げるため、2〜3か所の問題は出さない）。
- **1〜10問目：セレクトゾーン**（すべて選択式・3択）。選択肢をタップした時点で判定する。序盤（1〜3問目）は易しい問題から。
- **11問目〜：チャレンジゾーン**。11問目で「CHALLENGE ZONE！」を短く表示（タイマーは止めず、操作もさえぎらない）。記号入力の問題を約60%（`inputRatio`）、残りは選択式（理由・合同条件など）。
- 正解・不正解はすぐ判定し、○／× を約0.5秒表示して次の問題へ（解説は終了後の振り返りで）。○／× を表示している間は残り時間が減らない（Ver.1.0。`rank-game.js` の `pause`・`resume`。以前は約0.3秒で、その間も時間が進んでいた）。
- **誤答のペナルティ**：n 回目の誤答で制限時間が **4×n 秒** へる（1回目 −4秒、2回目 −8秒、3回目 −12秒…。合計は 4・8・…の和で、誤答が増えるほど重くなる）。「−4秒」をタイマーの下に短く表示する。ペナルティで制限時間を過ぎたら、その場で終了。
- **パス**：誤答と同じくミス1回（時間ペナルティもつく）として次の問題へ（正解数は増えない）。不正解後の再回答はできない。
- 一時停止はない。別タブ・端末のロック中も時間は進み、戻ったときに120秒を過ぎていれば終了する。再読み込みでは挑戦を再開しない（`#/rank/<コース>/play` を直接開くとトップへ戻る）。
- Ver.0.8 から、**基本の合同証明・総合証明の2コース**に分かれる（4-10）。以下のルール・タイマー・認定基準は2コース共通。
- 途中でやめるとき（左上の「やめる」）は「段位認定を途中で終了しますか？ 今回の記録は残りません。」と確認する。途中終了・画面の移動は記録しない。

**タイマー**

- 表示は「1:42」のような分:秒。残り30秒以下でオレンジ、10秒以下で赤（点滅はしない。10秒で短い音）。
- 残り時間は `performance.now()` と開始時刻の差から毎回計算する（`setInterval` の回数は数えない）。描画の遅れや端末の負荷で制限時間は延びない。
- 制限時間 ＝ 120秒 − 誤答のペナルティの合計。残り時間 ＝ 制限時間 − 経過時間（0未満にならない）。経過時間には、○／× を表示していた時間をふくめない。
- 残り0で解答の受付を終える。解答途中（未選択・未入力）は正解にもミスにも数えない。解答の確定と時間切れが重なったときは、確定した時刻が制限時間内かで判定する（ちょうど制限時間は時間内）。終了処理（結果の記録・結果画面への移動）は1回だけ。

**ミニ問題の種類**（`rank-questions.js` が50問の `evidence`・`congruence`・`triangles`・`finalStep`・`proofSteps`・`parallelogram` から生成。直角三角形・平行四辺形・四角形の分類のミニ問題は 4-10）

| タイプ | 例 | 形式 | カテゴリ |
|---|---|---|---|
| A 等しい辺・角 | △ABOと△DCOにおいて、対頂角は等しいから ＿＿＿ | 選択式／記号入力（等式） | 等しい辺・角 |
| B 等しい理由 | ∠AOC＝∠BOD が等しい理由は？ | 選択式 | 理由 |
| C 合同条件 | 図と「仮定：AB＝AC、Mは辺BCの中点」「結論：△ABM≡△ACM」を見て、使える合同条件は？（根拠は自分で見つける） | 選択式 | 合同条件 |
| E 合同からの結論 | △ABC≡△DEF より、AC＝＿＿（対応する辺・角） | 選択式／記号入力（左辺は固定） | 合同からの結論 |
| F 証明する三角形（STAGE 6） | AC＝BD を証明するために合同を示す三角形を、頂点の対応順に | 選択式／記号入力（三角形） | 三角形の対応 |
| 結論を導く理由（STAGE 6・7） | △AOC≡△BOD が証明できた。したがって AC＝BD と言える理由は？ | 選択式 | 合同からの結論 |
| 定理・三段論法（Ver.0.7） | 「AB＝ACのとき、等しい角は？」「AB＝ACより∠ABC＝∠ACB。その理由は？」「∠DCB＝∠DBCのとき、△DBCはどんな三角形？」「∠ACE＝∠ACD＋∠DCE を正三角形の角を使って表すと？」「③④の2つの式から、等しいと言える2つの角は？」「正三角形の1つの角は何度？」「2つの式の右辺が同じとき、何が言える？」 | 選択式（等しい角・式の比較は記号入力も） | 定理・三段論法 |

- 生成数：**449問**（Ver.1.0。同じ内容の問題はまとめる）。等しい辺・角 46、等しい理由 84、合同条件 34、三角形の対応 18（証明する三角形）、合同からの結論 165、定理・三段論法 19、直角三角形 33、平行四辺形 35、四角形の分類 15。記号入力でも出せる問題は225。どの問題も解答箇所は1つ。コースごとの出題数は 4-10。（Ver.0.9 は364問、Ver.0.8 は274問。以前の README の「276問」は、式の誤答の重複をまとめる前の数）
- 角の式のミニ問題（「∠ACE＝∠ACD＋∠DCE を、角の大きさを使って表すと？」）の誤答は、定数角を取りちがえた式（60°⇔90°）と符号を取りちがえた式。
- 「定理・三段論法」は Ver.0.7 で追加したカテゴリ。既存カテゴリの割合を崩さないよう、出題の重みを 0.5 にしている（`rank-config.js` の `categoryWeights`）。長い多段階証明はそのまま出題しない。導いた事実を使う根拠（理由が「③、④より」など）は、等しい辺・角／理由の問題にしない。
- 「対応する頂点は？」だけを問う問題は出さない（対応する辺・角・三角形を答える問題は出る）。
- **A は、選択肢がなくても答えが1つに決まる問題だけ**：その理由で言える、2つの三角形の辺・角どうしの等式が1つだけのとき。仮定に等式が2つある問題の「仮定より、＿＿」や、錯角が2組ある問題の「錯角より、＿＿」は出さない（例：p05 は「仮定より」は出ず、「対頂角より」が出る。三角形の外の角どうしの ∠AOC＝∠BOD は「△ABOと△DCOにおいて」の答えにならないので数えない）。
- 図が必要な問題（A・B・C・F）は、元の問題の図と仮定（C は結論も）を表示する（B は等式の辺・角を強調）。C（合同条件）の図には、**仮定で与えられた等しい辺・角だけ**印をつける（仮定の「AB＝AC」「∠POQ＝∠POR」「∠ABC＝∠DEF＝90°」と、理由が「仮定より」の根拠。共通な辺・対頂角・錯角など、仮定以外から言える関係には印をつけない。`rank-questions.js` の `givenMarks`）。p27 の AB のように途中に点がある線分は、寸法線の上に印をかく。合同の式から答える問題（E）は図を出さない（図の見た目から答えを推測させない）。
- スマホ縦画面では、上部（タイマー・図）を固定し、問題文・選択肢・キーパッドの部分だけがスクロールする。
- 記号入力は既存の数学キーパッド（`math-keypad.js`）を使う。辺・角の種類が問題から決まるときは最初から入力形式を設定する（E は「AC＝＿＿」のように左辺を固定、F は三角形の入力）。キーパッドは段位認定用にコンパクト。

**正誤判定**

- 文字列の比較ではなく、既存の `geometry.js`・`validation.js` で判定する：辺の両端の順序、等式の左右の交換、角の逆順、一直線上の点による角の別名、三角形の頂点の対応、根拠の組と合同条件。
- **同じ数学的関係を表す正しい表記は正解**（例：p01 の共通な辺は BD＝BD・DB＝BD・BD＝DB のどれでも正解。角は ∠BAO＝∠BAC のような一直線上の別名も正解）。頂点の順序を判定するのは、問題が「頂点の対応順に」と明示する F だけ。
- 選択肢は、正解がちょうど1つになるように作る（誤答の選択肢に `extraTruths` や根拠を使わない。E の誤答は図の上でも等しくない辺・角だけ。理由の誤答は、その等式に使っても正しくならない理由だけ）。`npm test` で全問題を別の方法で確かめている。

**出題の抽選**（`rank-game.js`）

- 乱数のシードを記録し、毎回出題順と選択肢の並びが変わる（テストではシードを固定して同じ順番を再現）。
- 7つのカテゴリ（等しい辺・角／理由／合同条件／三角形の対応／合同からの結論／定理・三段論法／直角三角形）のうち、そのコースで出せるものの中から「出題数 ÷ 重み」が小さいものを選ぶ（証明する三角形は難しいので11問目から）。重みはコースの設定（`rank-tracks.js` の `categoryWeights`）。
- 未出題の候補があるうちは同じ問題を出さない。同じ元問題が続かないようにする。候補を使い切ったら、直近の問題を避けて再利用する（候補が少なくても止まらない）。
- パスしても難易度の分布は変わらない（易しい問題だけを探すことはできない）。

- 段位・制限時間・時間ペナルティ（`penaltyStepMs`）・出題割合・コンボの演出は `rank-config.js` に集約している（画面や判定に数値を直接書かない）。基準を変えるときは `criteriaVersion` を上げる。
- 認定基準のバージョンは 2（Ver.0.6 の最初の版の「有効正解数 ＝ 正解数 − ミス数×0.5」から、「正解数＋時間ペナルティ」に変更したため）。バージョン1で認定した最高段位は、比べずに `previous` に残る。

**連続正解（コンボ）**：正解で+1、不正解・パスで0。3連続「NICE！」、5「GREAT！」、10「EXCELLENT！」、15「AMAZING！」を画面の端に短く表示。得点のボーナスはない（演出と最高連続正解の記録のみ）。

**結果発表**：「総合証明｜段位認定結果」のようにコース名を表示し、認定段位（10級〜1級はシンプル、初段〜五段はメダル、六段〜十段はゴールド、皆伝は王冠）、正解数・ミス数（パスの数）・時間ペナルティの合計・最高連続正解、次の段位まであと何問か、自己ベスト更新なら「NEW RECORD！」。ボタン：もう一度挑戦！（同じコース）／間違えた問題を確認／段位一覧へ／コースを選ぶ。

**誤答の振り返り**（`#/rank/<コース>/review`）：そのコースの直近の挑戦で、まちがえた問題とパスした問題を一覧表示（問題番号・種類・問題文・あなたの解答・正解・解説・図）。「元の問題を解く」でハンターモードの元の問題へ移れる（結果は直近1回分を保存しているので消えない）。

### 4-8. 多段階証明（Ver.0.7、STAGE 7「証明をつなげろ！」）

**「見つけた根拠を使って、新しい根拠を導く！」**。問題データに `proofSteps` を持つ問題（p21〜p24）は、次の順に進む。p01〜p20 は従来どおり（変更なし）。

```text
ハンター：三角形の選択（結論が辺・角の等しさのとき） → 3つの根拠 → 合同条件 → 最終結論 → 後半のステップ（例：二等辺三角形である）
            └ 理由1つでは言えない根拠（∠BAD＝∠CAE など）は「詳しい理由を説明する」→ 前半のステップ（定理・角の式・式の比較）
パズル  ：三角形 → 前半のステップの行 → 根拠の行 → 合同条件 → 最終結論 → 後半のステップ（証明文の順）
```

方針：**理由の中で完結する短い推論は1ステップ**（定理は理由を1回選んで完了）。**複数の式を比べる推論・導いた結果を次に使う推論は独立したステップ**にする。

**推論ルール**（`js/proof-rules.js`）

| ルールID | 内容 | ゲームでの使い方 |
|---|---|---|
| `isoscelesBaseAngles` | 二等辺三角形の底角は等しい | 「AB＝ACより、【理由】 ∠ABC＝∠ACB」（定理のステップ） |
| `isoscelesConverse` | 2つの角が等しい三角形は二等辺三角形 | 最終結論 ∠DCB＝∠DBC のあと「【理由】 △DBCは二等辺三角形」（後半のステップ） |
| `equilateralSides` | 正三角形の3辺は等しい | 根拠の理由（「正三角形の辺より」） |
| `equilateralAngles` | 正三角形の1つの角は60° | 角の式の中で使う（∠DCE＝60°） |
| `angleAddition` / `angleSubtraction` | 角の和・差 | 「（△DCEは正三角形）∠ACE＝∠ACD＋∠DCE＝【∠ACD＋60°】」（角の式のステップ。Ver.1.0 から、□に入る式を選ぶ） |
| `equalExpressions` | 同じ式に等しい2つの角は等しい（三段論法） | 「③、④より、∠ACE＝∠BCD」（式の比較のステップ） |
| `triangleCongruence`・`correspondingSides`・`correspondingAngles` | 合同・対応する辺／角 | 既存のしくみ（合同条件・最終結論） |

**ステップの状態**（`js/proof-engine.js`）：`locked`（前提がまだない）／`available`（解ける）／`completed`（証明した）。依存のないステップ（例：p23 の2つの角の式）はどの順番で解いてもよい。正解すると結論が「証明済みの事実」として登録され、後のステップや合同の根拠で使える。**まだ証明していない事実を根拠にすると「その関係を使うには、先に証明する必要があるよ！」**（`not-proved`）。

**ハンターモード**

- **解答の順は「三角形 → 根拠 → 合同条件 → 結論」**（Ver.0.8 で変更。以前は根拠の前にステップを解いていた）。根拠の収集で2つの要素を選ぶと、理由の選択肢の下の「📝 詳しい理由を説明する」が押せるようになる（どの組を選んでも押せるので、正解かどうかは押すまで分からない）。
  - 前のステップで導く根拠（例：p24 の ∠BAD＝∠CAE）を選んで押すと、そのステップ（定理を使う／角の式／式を比べる）を解く画面へ進む。解きおえると、その根拠が「導いた等式」として登録されて根拠の収集にもどる。「◀ 根拠の選択にもどる」で途中でもどれる（解いたステップは証明済みのまま）。
  - 理由を1つ選ぶだけで言える根拠で押すと「それは、理由を1つ選ぶだけで言える関係だよ」、等しくない組なら「まだ言えないよ」（どちらもミス）。説明が必要な根拠に理由を選んで確定すると「理由を1つ選ぶだけでは言えないよ。『詳しい理由を説明する』で説明しよう！」（ミス）。「導いた等式より」は理由の選択肢に出さない。
  - 直角三角形の問題（p27・p30）では、鋭角の欄を選んでから説明する。
- パネルの上に手順（①三角形 ②根拠（↳定理を使う／角の式／式を比べる） ③合同条件 ④結論 …）を表示し、完了は緑、今のステップは青。解けるステップが2つ以上なら、タブで選べる。
- 定理：理由を3択から選んで「決定」。角の式（p23・p24・p30）：Ver.1.0 から、理由ではなく「∠ACE＝∠ACD＋∠DCE＝□」の□に入る式を3択から選ぶ（誤答は定数角を取りちがえた式（60°⇔90°）と符号を取りちがえた式。`game.js` の `expressionOptions`。証明パズルも同じ）。式の比較：2つの式の左辺・右辺がボタンになっていて、**同じ部分（右辺）を2つタップすると「2つの式の右辺が同じだね！」**と緑で強調 → 「詳しい理由を説明する」で最初に選んだ2つの角（例 ∠BCD＝∠ACE）が等式の欄に入った状態になるので、「決定」を押すだけ（同じ角をもう一度選ばせない）。正解で「新しい根拠を発見！」。
- 説明して登録した根拠のスロットは「導いた等式」。スロットの下に「証明済みの事実」の一覧（タップすると図が光る）。証明文は従来どおり（ステップの行の番号を使って「①、②、⑤より」）。
- 誤答（理由・比較の等式）はミス1回（同じ誤答のくり返しでは増えない）。ヒントはステップごとに3段階（最終段階でも自動では答えない）。

**証明パズル**（証明文の中にステップの行が入る）

| レベル | 定理・角の式 | 式の比較 |
|---|---|---|
| おてがる | 定理は理由カード、角の式は□に入る式のカード（Ver.1.0） | 2つの式の**共通部分**をカードから選ぶ（結論 ∠ACE＝∠BCD は自動で表示） |
| スタンダード | 定理は理由カード、角の式は□に入る式のカード | **比べる2つの式**（③と④／③と③／④と④）＋ **導ける等式**を3択 |
| チャレンジ | 定理は理由カード、角の式は□に入る式のカード | 比べる2つの式 ＋ 導ける等式を**数学キーパッドで入力**（左右の入れかえ・角の別表記も正解） |

- 根拠の行は、導いた事実を使わない根拠だけ（導いた事実はステップの行で書き、合同のまとめで「①、②、⑤より」と番号を使う）。導いた等式を根拠の行に入れると「その等式は、ステップで導いた等式（⑤）だよ」。同じ式を2回選ぶと「同じ式を2回選んでも、新しい等式は導けないよ」。
- ヒントの順：三角形 → 前半のステップ → 根拠 → 合同条件 → 最終結論 → 後半のステップ。

**完成した証明文**（例：p23）

```text
△ACEと△BCDにおいて
正三角形の3辺は等しいから AC＝BC ……①
正三角形の3辺は等しいから CE＝CD ……②
角の和より（△DCEは正三角形）、∠ACE＝∠ACD＋∠DCE＝∠ACD＋60° ……③
角の和より（△ABCは正三角形）、∠BCD＝∠BCA＋∠ACD＝∠ACD＋60° ……④
③、④より、∠ACE＝∠BCD ……⑤
①、②、⑤より、2組の辺とその間の角がそれぞれ等しいので、△ACE≡△BCD
したがって、合同な図形の対応する辺は等しいから、AE＝BD
```

ステップの行・式をタップすると、図の対応する辺・角が光る。p22 は最後に「∠DCB＝∠DBCより、2つの角が等しい三角形は二等辺三角形だから、**△DBCは二等辺三角形**」。

**角度式の判定**（`js/angle-expression.js`）

- 式は文字列で比べず、`{ terms: { 角のキー: 係数 }, constant: 定数角 }` に構造化して比べる。`∠ACD＋60°`・`60°＋∠ACD`・`∠DCA＋60°` は同じ式（角の別表記・一直線上の別名は `geometry.js` の角のキーで同一視）。`60°－∠DAC` は係数 −1。同じ角を足して引くと消える。
- 読めない式は null（例外でゲームを止めない）。一般の数式処理はしない（角と定数角の和・差だけ）。
- 図の座標で測った値は、問題データの整合性の確認（`verifyProblem`）だけに使う。**ゲームの正誤判定は、証明済みの事実と推論ルール・問題データの正解で行う**（図の上で同じ大きさに見えるだけでは正解にしない）。

### 4-9. 直角三角形の合同（Ver.0.8、STAGE 8「直角三角形を攻略せよ！」）

**「なぜその三角形は直角三角形なのか」「どの辺が斜辺なのか」「他のどの辺・角が等しいのか」を考えて、合同条件を選ぶ。**

**合同条件**（`PH.CONDITIONS`。中学数学の標準的な表現）

| ID | 合同条件 | 必要な根拠 |
|---|---|---|
| `SSS` | 3組の辺がそれぞれ等しい | （従来どおり） |
| `SAS` | 2組の辺とその間の角がそれぞれ等しい | （従来どおり） |
| `ASA` | 1組の辺とその両端の角がそれぞれ等しい | （従来どおり） |
| `RHA` | 直角三角形の斜辺と1つの鋭角がそれぞれ等しい | 直角 ＋ 斜辺 ＋ 鋭角 |
| `RHS` | 直角三角形の斜辺と他の1辺がそれぞれ等しい | 直角 ＋ 斜辺 ＋ 他の1辺 |

**判定の仕様**（`js/right-triangle.js`。判定は `validation.deriveCondition` から呼ぶ共通の関数1つ）

- **直角三角形であることは証明上の前提**として根拠に入れる（`evidence` の `role: 'right'`。表示は「∠ABC＝∠DEF＝90°」）。図で直角に見えるだけでは認めない。90°と言える理由は、**仮定より**（仮定に「∠ABC＝∠DEF＝90°」）／**垂直な2直線がつくる角だから**（仮定に「BD⊥AC」）／**正方形の角だから**（仮定に「四角形ABCDは正方形」）のどれか（データの検証で、図と仮定から本当に言えるかを確かめる）。垂直から言える直角は、仮定に「BD⊥AC」などが書かれているので「仮定より」も正解にする（ハンター・パズル。`PH.acceptedReasons`。証明文の標準の書き方は「垂直な2直線がつくる角だから」）。正方形の角は、仮定が「四角形ABCDは正方形」なので「正方形の角だから」だけを正解にする。
- **斜辺は直角の位置から求める**：直角の頂点（2つの三角形の対応する頂点）をふくまない辺が斜辺、ふくむ辺が他の1辺、直角以外の角が鋭角。辺の長さや図の見た目では決めない。データに斜辺を二重に書かない。
- 根拠の組（3つ）から言える条件：直角＋斜辺＋他の1辺 → RHS、直角＋斜辺＋鋭角 → RHA、直角＋直角をはさむ2辺 → SAS、直角＋（直角と鋭角の間の辺）＋鋭角 → ASA。対応していない辺・角、同じ組が2回、直角が2組などは不成立。
- **直角の根拠がない組からは RHS・RHA にならない**。まだ確かめていない直角・まだ証明していない等式（導いた事実）は使えない。
- 直角三角形の問題で3つの合同条件を選んだときは、「3つの合同条件で示せる場合もあるけれど、今回集めた根拠（直角・斜辺・他の1辺）には、直角三角形の合同条件がぴったり合うよ。選び直そう！」と案内し、**ミスに数えない**（数学的に別の道すじで示せる条件を、単純な誤りとは扱わない）。もう一方の直角三角形の条件（RHS⇔RHA）はミス。
- 通常の問題（p01〜p24）は従来の3択のまま。直角三角形の問題だけ5択になる。

**ハンターモードの操作**

- 根拠の欄が「**直角**」「**斜辺**」「**他の1辺**（RHS）／**鋭角**（RHA）」になる。今集めている欄を見出し（「いま集める根拠：斜辺（直角に向かい合う辺）」）とスロットの枠で示し、空いている欄をタップすると切りかえられる。直角・鋭角の欄では角選択、斜辺・他の1辺の欄では辺選択に自動で切りかわる。
- 直角の欄：2つの三角形の直角をタップ → 「90°と言える理由」（仮定より／垂直な2直線がつくる角より／正方形の角より）を選ぶ。正しければ「直角三角形を確認！」で、その直角に緑の直角の印（小さな四角）がつく。自動表示の印なので「消す」では消えない。確かめた直角は「確かめた事実」として登録する（多段階証明の問題では証明エンジンの事実にも登録する）。
- **今の欄に合わない根拠は正解にしない**（例：斜辺の欄に他の1辺 AB＝CB →「AB＝CB は等しいけれど、斜辺ではなく『他の1辺』だよ。斜辺は、直角に向かい合う辺だよ。」）。根拠そのもの（等式と理由）が正しく、答える欄の順番だけがちがうときは**ミスに数えない**（Ver.0.9 で変更。メッセージは同じ。理由もまちがっているときはミス）。「詳しい理由を説明する」で今の欄に合わない根拠を選んだときも同じ。対応順・理由の判定は従来どおり。
- 斜辺を見つけると、図の斜辺をオレンジで強調する。図の直角の印は、仮定・垂線の直角だけ最初から表示する（正方形の角など、導く直角は確かめるまで表示しない）。
- ヒントは今集めている欄の根拠の3段階（直角：「2つの三角形の中に90°の角はあるかな？」→「垂直な線や正方形の角に注目しよう！」→「この2つの角が直角であることを確認しよう。」、斜辺：「直角三角形のどの辺が斜辺かな？」…、鋭角：「斜辺のほかに、等しい角はないかな？」…）。合同条件のヒントも RHS・RHA 用。

**証明パズル**（3レベルすべて）

| レベル | 直角の行 | 斜辺・他の1辺（鋭角）の行 | 合同条件 |
|---|---|---|---|
| おてがる | 等式「∠ABC＝∠DEF＝90°」と理由を表示済み | 理由は表示済み、等式をカードで選ぶ | 5つのカードから選ぶ |
| スタンダード | 等式は表示済み、**直角である理由**（仮定より／垂直な2直線がつくる角だから／正方形の角だから）を選ぶ | 理由と等式のカードを組み合わせる | 5つのカードから選ぶ |
| チャレンジ | 等式は表示済み、直角である理由を選ぶ（90°の式は入力しない） | 理由はカード、等式は**数学キーパッドで入力** | 5つのカードから選ぶ |

- 行には役割のラベル（直角・斜辺・他の1辺・鋭角）がつく。斜辺の行に他の1辺を入れると「それは斜辺ではなく『他の1辺』だよ。斜辺は、直角に向かい合う辺だよ。」（ミス）。
- 直角の等式は表示済みなので、等式カードには出さない。直角専用の理由（垂直・正方形の角）は、直角の行のカードにだけ出す。
- 3つの合同条件のカードを入れたときは赤くするがミスに数えない（ハンターと同じ案内）。

**完成した証明文**（例：p28・p30）

```text
△CEDと△CFBにおいて
正方形の角だから ∠CDE＝∠CBF＝90° ……①
正三角形の3辺は等しいから CE＝CF ……②
正方形の4辺は等しいから CD＝CB ……③
①、②、③より、直角三角形の斜辺と他の1辺がそれぞれ等しいので、△CED≡△CFB
したがって、合同な図形の対応する角は等しいから、∠ECD＝∠FCB
```

```text
△ABDと△CAEにおいて
垂直な2直線がつくる角だから ∠ADB＝∠CEA＝90° ……①
仮定より AB＝CA ……②
三角形の内角の和は180°だから（△ABDで、∠ADB＝90°）、∠ABD＝180°－(90°＋∠DAB)＝90°－∠DAB ……③
角の差より（∠BAC＝90°）、∠CAE＝∠BAC－∠DAB＝90°－∠DAB ……④
③、④より、∠ABD＝∠CAE ……⑤
①、②、⑤より、直角三角形の斜辺と1つの鋭角がそれぞれ等しいので、△ABD≡△CAE
```

**多段階証明との接続**：p27 は二等辺三角形の底角（`isoscelesBaseAngles`）、p30 は三角形の内角の和（新しいルール `triangleAngleSum`）・角の差・三段論法（Ver.0.7 の証明エンジン）を使う。角の式で数に置きかえる角は、大きさが仮定から分かっている角（正三角形の角 60°、仮定・垂直・正方形の直角 90°）だけ（`proof-rules.knownAngles`）。

### 4-10. 段位認定の2コース（Ver.0.8）

段位認定のトップで、2つのコースから選んで挑戦する。**2つのコースの段位・記録は完全に別々**（最高段位・最高正解数・最高連続正解・挑戦回数・直近の結果・直近の誤答）。

| コース | 表示名・説明 | 出題範囲 |

- **STAGE 9「平行四辺形を利用せよ！」**（p37〜p39）：仮定の平行四辺形の性質（対辺は等しい・対辺は平行 → 錯角・対角線はそれぞれの中点で交わる）を、三角形の合同の根拠に使う。手順は STAGE 1〜8 と同じ（p38 は直角三角形の合同）。問題データの `knownParallelograms` に仮定の平行四辺形を書き、性質の理由は、その性質から本当に言えるかを `npm test` で確かめる。
- **STAGE 10「平行四辺形を証明せよ！」**（p31〜p34・p36・p40〜p42）：四角形が平行四辺形になることを証明する（以下）。
- **STAGE 6 の p35**：合同から導いた錯角の等しさから「錯角が等しいから平行」で AD∥BC を示す（結論の種類 `parallelLines`。最終結論のあとの後半のステップ `alternateAnglesParallel`。誤答の選択肢に逆の推論「平行線の錯角は等しいから」）。

**「何を示せば平行四辺形といえるのか」を考え、その条件を満たすための根拠を見つける。** 5つの成立条件を暗記するだけでなく、ゴール（平行四辺形）から必要な条件を逆算し、根拠を集めて証明を完成させる。

**平行四辺形の性質**（`js/parallelogram-rules.js`。「平行四辺形である → …」。**平行四辺形だと分かっている四角形にだけ使える**）

| ルールID | 導けること | 理由（REASONS） |
|---|---|---|
| `parallelogramOppositeSidesParallel` | 2組の対辺がそれぞれ平行 | 平行四辺形の対辺は平行だから（`parallelogramParallel`） |
| `parallelogramOppositeSidesEqual` | 2組の対辺がそれぞれ等しい | 平行四辺形の対辺は等しいから（`parallelogramSides`） |
| `parallelogramOppositeAnglesEqual` | 2組の対角がそれぞれ等しい | 平行四辺形の対角は等しいから（`parallelogramAngles`） |
| `parallelogramDiagonalsBisect` | 対角線がそれぞれの中点で交わる | 平行四辺形の対角線はそれぞれの中点で交わるから（`parallelogramDiagonals`） |

**平行四辺形になるための5つの条件**（`PH.PARALLELOGRAM_CONDITIONS`。「… → 平行四辺形である」。性質とは逆向きの推論）

| ID | 成立条件 | 必要な根拠（四角形ABCD） |
|---|---|---|
| `PP_PARALLEL_PAIRS` | 2組の対辺がそれぞれ平行（定義） | AB∥DC、AD∥BC |
| `PP_EQUAL_SIDES` | 2組の対辺がそれぞれ等しい | AB＝DC、AD＝BC |
| `PP_EQUAL_ANGLES` | 2組の対角がそれぞれ等しい | ∠DAB＝∠BCD、∠ABC＝∠CDA |
| `PP_BISECT_DIAGONALS` | 対角線がそれぞれの中点で交わる | AO＝CO、BO＝DO（O は対角線ACとBDの交点） |
| `PP_PARALLEL_EQUAL_PAIR` | 1組の対辺が平行で、その長さが等しい | AB∥DC と AB＝DC（または AD∥BC と AD＝BC） |

**判定の仕様**（判定の関数は `deriveParallelogramCondition({ figure, vertices }, establishedFacts)` 1つ。返り値は成り立つ条件のIDと、使った事実のID）

- 四角形は周に沿った順の頂点（`targetQuadrilateral`）で扱い、対辺・対角・対角線を頂点の順から求める（`js/quadrilateral.js`）。隣り合う辺・角や対角線を対辺・対角と取りちがえない。
- **退化した四角形（3つの頂点が一直線上）・自己交差した四角形（8の字）では、どの条件も成り立たない**。
- ④は、交点 O が図の点で、`figure.lines` の上で**両方の対角線の内側**にあるときだけ（AO＝CO・BO＝DO の等式が登録されているだけでは成り立たない）。
- ⑤は、**平行な辺と等しい辺が同じ1組の対辺**のときだけ（AB∥DC と AD＝BC では成り立たない。等脚台形の場合がある）。
- 平行の関係は `{ rel: 'parallel', items: ['AB', 'DC'] }` で表し、AB∥CD・CD∥AB・BA∥DC は同じ関係。一直線上の点による別表記（E が AB 上なら EB∥DF は AB∥DF）も `figure.lines` で同じ関係にする。
- **平行を導く推論**：錯角（`alternateConverse`）・同位角（`correspondingConverse`）が等しいならば2直線は平行。等しい2つの角が、どの2直線とそれを横切るどの直線でできた錯角・同位角かを、図の配置で確かめる（`checkConverse`。等しい角が2つあるだけでは平行と認めない）。ゲームでは、その角の等しさが証明済みのときだけ使える（まだなら「錯角・同位角が等しいことを、先に証明する必要があるよ！」）。
- 図の見た目（長さ・角度・平行に見えること）では判定しない。図の座標は、データの確認（`npm test`）と、退化・自己交差・錯角か同位角かの向きの確認だけに使う。
- **ほかの道すじの条件**：数学的に別の成立条件でも示せる場合（`alternatives`。データで指定する。現在の問題では使っていない）、その条件を選んでも**ミスにしない**で「その条件でも平行四辺形といえる場合があるよ。今回は集めた根拠を使って考えよう！」と案内する。

**ハンターモードの操作**

- 問題文の結論は「四角形ABCDは平行四辺形」。図では証明する四角形を薄い緑で表示する。図の右のボタンは「**四角形確認**」になり、対辺・対角を組ごとに同じ色（青・オレンジ）で強調し、対角線（点線）と交点を表示する。
- 根拠の欄の数は問題ごと（STAGE 10 は2つ）。手順の表示は「① 平行四辺形の根拠 → ② 成立条件」（p42 は「三角形 → 合同の根拠 → 合同条件 → 角の等しさ（合同から導く結論）→ 平行四辺形の根拠 → 成立条件」）。
- 辺を2つ選ぶと、等式の候補の間の記号が「**＝⇔∥**」ボタンになる。平行を示すときは ∥ に切りかえてから理由を選ぶ（角どうしは ＝ だけ）。根拠を確定すると ＝ にもどる。
- 理由の選択肢：仮定より・平行四辺形の性質（対辺は等しい／対辺は平行／対角は等しい／対角線）・錯角が等しいから（平行）・同位角が等しいから（平行）など（問題ごとに `parallelogram.reasons`）。
- 2つの根拠がそろうと、5つの成立条件から選んで「証明を完成する」。見つけた平行の根拠には、図に緑の矢印がつく。

### 4-12. 特別な平行四辺形（Ver.1.0、STAGE 11「特別な平行四辺形」）

ひし形・長方形の性質を使う証明と、四角形がひし形・長方形になることの証明。証明のゴール（4つの辺・角がすべて等しい）から必要な条件を逆算し、複数の根拠を組み合わせる。

**四角形の分類（`js/special-quadrilaterals.js`）**

- 種類：`QUADRILATERAL_TYPES = { parallelogram: '平行四辺形', rhombus: 'ひし形', rectangle: '長方形', square: '正方形' }`。
- 包含関係：ひし形・長方形は平行四辺形。正方形はひし形でも長方形でもある（平行四辺形でもある）。`implied(type)`（その種類なら言える種類）・`isA(type, sup)`。**一般的な種類から特別な種類へは、成立条件がなければ変換しない**（平行四辺形 → ひし形 にはならない）。
- 成立条件（`PH.SPECIAL_CONDITIONS`。ルールIDは `proof-rules.js` の `PH.PROOF_RULES` と同じ）：

| 種類 | 条件ID | 条件 | 前提 |
|---|---|---|---|
| ひし形 | `rhombusDefinition` | 4つの辺がすべて等しい（定義） | なし |
| ひし形 | `rhombusAdjacentEqual` | 平行四辺形で、となり合う2辺が等しい | 平行四辺形 |
| ひし形 | `rhombusDiagonalPerpendicular` | 平行四辺形で、対角線が垂直に交わる | 平行四辺形 |
| 長方形 | `rectangleDefinition` | 4つの角がすべて等しい（定義） | なし |
| 長方形 | `rectangleOneRightAngle` | 平行四辺形で、1つの角が直角 | 平行四辺形 |
| 長方形 | `rectangleDiagonalsEqual` | 平行四辺形で、対角線の長さが等しい | 平行四辺形 |
| 正方形 | `squareDefinition` | 4つの辺がすべて等しく、4つの角がすべて等しい | なし |
| 正方形 | `squareRectangleAdjacent` | 長方形で、となり合う2辺が等しい | 長方形 |
| 正方形 | `squareRhombusRightAngle` | ひし形で、1つの角が直角 | ひし形 |
| 正方形 | `squareDiagonals` | 平行四辺形で、対角線の長さが等しく、垂直に交わる | 平行四辺形 |

- **前提を確かめる**：「対角線が垂直に交わる」だけ・「対角線の長さが等しい」だけでは、ひし形・長方形と判定しない（平行四辺形だと分かっているときだけ）。
- 2つの使い方：① 性質の記号（`adjacentSidesEqual`・`oneRightAngle`・`diagonalsEqual` など）による分類 `guaranteedTypes(base, atoms)`・`classify(base, atoms)`（段位認定の分類の問題）。② 図の事実（等式・直角）による成立条件の判定 `deriveSpecialCondition({ figure, vertices, knownTypes }, facts)`（ハンター・パズル）。「4つの辺がすべて等しい」は、辺の等式をつないで判定する（AB＝DC、AD＝BC、AB＝AD → AB＝BC＝CD＝DA）。
- 証明済みの事実：`ProofEngine` に四角形の種類 `{ kind: 'quadrilateralType', vertices, type }` を登録できる（`establishType`・`hasType`・`typeFacts`）。仮定の「四角形ABCDは平行四辺形／ひし形」は最初から登録され、正方形と登録すれば長方形・ひし形・平行四辺形としても使える。ひし形・長方形を証明しおえると、ハンターはその種類を事実として登録する（`game.provedType`）。

**新しい推論ルール**（`proof-rules.js`）：平行四辺形の隣り合う角の和は180°（`parallelogramAdjacentSupplementary`。∠A＝90° → ∠B＝180°－90°＝90° を1ステップ）、平行線の錯角（`parallelAlternateAngles`。平行は仮定の平行四辺形の対辺）、角の二等分線（`angleBisector`。仮定「ACは∠BADの二等分線」）、同じ角に等しい2つの角は等しい（`angleTransitive`）、2つの角が等しい三角形は二等辺三角形で、その2辺が等しい（`isoscelesConverseSides`）、中点（`segmentMidpoint`。根拠の理由 `midpoint`「中点より」。「仮定より」でもよい）。新しい理由：`rhombusSides`（ひし形の4辺は等しい）・`rhombusAngles`（ひし形の対角は等しい。「平行四辺形の対角は等しい」でもよい）・`midpoint`。

**ハンターモード**

- p43：従来の直角三角形の証明（直角 → 斜辺 → 鋭角）。ひし形の性質（4辺・対角）を根拠にする。
- p44・p45：四角形の根拠を集め（導く根拠は「詳しい理由を説明する」でステップを解く）、成立条件を選ぶ。根拠がそろうと「集めた根拠から AB＝BC＝CD＝DA」のように **4つの辺（角）がすべて等しいことを表示する**（4辺の等式を全文入力させない）。成立条件は **「4つの辺がすべて等しい」「4つの角がすべて等しい」「4つの辺と角がすべて等しい」の3択**（問題データの `choices`。ハンター・パズル共通）。
- 成立条件の判定：ほかの種類の条件（ひし形の問題で「4つの角がすべて等しい」）は「それは長方形になるための条件だよ！」、「4つの辺と角がすべて等しい」は「それは正方形になるための条件だよ！」でミス。
- 証明する四角形のひし形・長方形としての性質（「ひし形の4辺は等しい」など）を、証明する前に使うとミス（「それは、四角形ABCDがひし形だと証明できてから使える性質だよ！」）。

**証明パズル**：6問すべて3レベル。根拠の行の等式・理由はこれまでと同じ（チャレンジは辺・角の等式をキーパッドで入力）。「AB＝BC＝CD＝DA」の行は表示済み。**ひし形・長方形の成立条件はカードで選ぶ**（キーパッドで「ひし形」などと入力しない）。

```text
平行四辺形ABCDにおいて（p44）
平行四辺形の対辺は等しいから　AB＝CD ……①
平行四辺形の対辺は等しいから　AD＝BC ……②
仮定より　AB＝AD ……③
①、②、③より、AB＝BC＝CD＝DA
4つの辺がすべて等しいので、四角形ABCDはひし形である。
```

### 4-13. 証明の間違い探し（Ver.1.1、第4のモード）

**証明文に隠された間違いを見つけろ！** 完成した証明文を読み、数学的・論理的な間違いを見つける力を育てる（定期テストで自分の証明を見直す力：等式・理由・合同条件・頂点の対応・証明の順序）。段位認定とは別のモードで、制限時間はない（段位認定の問題には入れない）。

**遊び方**

1. タイトル画面の「証明の間違い探し」から問題を選ぶ（単元別の一覧）。
2. 図・仮定・結論と、間違いを1か所ふくむ証明文を見比べる。
3. 間違っていると思う行をタップして選ぶ（もう一度タップで解除。別の行をタップで選び直し）。**タップしただけでは判定しない。**
4. 「ここが間違い！」で判定する（行を選んでいないときは押せない）。
5. 正解なら「間違い発見！」と解説。不正解なら、その行を赤く表示して「この行は正しいよ。ほかの行も確認してみよう！」（正解の行は見せない）。同じ行をもう一度選んでもミスは増えない。
6. 3回まちがえると「ヒントを見る」「正解を確認する」が出る（ヒントはタイトルバーの「ヒント」からいつでも見られる）。

**判定の方針**：1問の間違いは1か所。等式を変えると後の合同条件も導けなくなるように、間違いが後の行に影響する場合は、**それまでの行を正しいとしたとき、最初に論理がくずれる行**を正解とする（画面に「最初に論理がくずれる行をタップしよう」と表示）。

### 4-14. ランダム5問チャレンジ・2コース・誤りバリエーション（Ver.1.2）

**同じ証明でも、間違いは毎回変わる！** 証明の間違い探しに、2つのコースから選ぶ **ランダム5問チャレンジ** を追加し、既存30問それぞれに **誤りのバリエーション**（間違いの場所・種類のちがう版）を用意した。何度挑戦しても、正解の行の位置を覚えるだけでは解けない。

#### ランダム5問チャレンジ

間違い探しの問題選択画面で、ヘッダーのすぐ下の切り替えボタン「📝 じっくり練習」「🎯 ランダムチャレンジ」（横並び。選んでいるほうを緑で表示）から「ランダムチャレンジ」→ コースを選ぶ → 5問に挑戦 → 結果発表 → 振り返り。「じっくり練習」で問題一覧にもどる（どちらの画面もヘッダーは「証明の間違い探し」、戻るボタンはホームへ）。

| 項目 | 仕様 |
|---|---|
| 出題数 | 5問（同じベース問題は1回の挑戦で1回だけ） |
| 制限時間 | なし |
| 解答 | 間違っている行をタップ →「ここが間違い！」で確定（1問につき1回だけ。確定後は選び直せない） |
| ヒント | なし |
| 得点 | 正解20点・不正解0点、100点満点 |
| 正解したとき | 正解音・大きな ○・「+20点」→「次の問題へ」 |
| 不正解のとき | 不正解音・大きな ×・「0点」→「次の問題へ」（正解の行・解説はチャレンジ中は見せない） |
| 途中でやめる | 「チャレンジを途中で終了しますか？ 今回の記録は残りません。」で確認。途中終了は、どちらのコースの記録も変えない |
| 再読み込み | 途中の挑戦は再開しない（コースを選ぶ画面に戻る） |

プレイ画面は、じっくり練習と同じ（図・仮定・結論を固定して証明文だけスクロール、図をタップして印つけ）。上部に「証明の間違い探し／（コース名）」と「Q3 / 5」「得点」を表示する。

**結果発表**：コース名、得点（100点満点）、正解数・不正解数、Q1〜Q5 の ○×、自己ベスト更新（初挑戦は「更新」と言わない）、そのコースの最高得点。メッセージは 100点「PERFECT！ 証明の達人！」、80点「EXCELLENT！ 見直し上手！」、60点「GOOD！ あと一歩！」、0〜40点「間違いを見抜く力を磨こう！」。ボタンは「同じコースでもう一度挑戦」「間違えた問題を確認」（全問正解なら「問題を振り返る」）「コースを選ぶ」「間違い探しトップへ」。

**振り返り**：挑戦した5問を、保存した **ベース問題ID・バリエーションID** からそのまま再現する（再抽選しない）。各問題に、問題番号・コース名・ベース問題（間違い探し番号と元の問題）・誤りの種類・図・仮定・結論・**出題された証明**（正解の行を黄色、自分が選んだ行（不正解のとき）を赤）・自分が選んだ行・間違いがある行（正解の行）・正しい文・解説・正しい証明全文（開閉式）を表示する。

#### 2つのコース

コースID・表示名は段位認定と共通（`basic`「基本の合同証明」／`comprehensive`「総合証明」）。記録は段位認定とは別。

| コース | 内容 | 出題できるベース問題 | バリエーション |
|---|---|---|---|
| 基本の合同証明 `basic` | 3つの合同条件（SSS・SAS・ASA）、共通な辺・角、対頂角、平行線の錯角・同位角、仮定、頂点の対応、合同な図形の対応する辺・角、論理の順序 | **16問**（基本の合同証明12問・合同から結論を導く4問） | **64通り** |
| 総合証明 `comprehensive` | 基本のすべてに、二等辺三角形・正三角形・三段論法・直角三角形の合同・平行四辺形の性質と成立条件・ひし形・長方形・錯角が等しいから平行 | **30問**（4単元すべて） | **119通り** |

総合証明の単元別：基本の合同証明12問・48通り、合同から結論を導く5問・20通り、三角形の性質・直角三角形6問・27通り、平行四辺形・特別な平行四辺形7問・24通り。

**出題範囲の決め方（requiredTopics）**：ステージ番号ではなく、**必要な知識** で決める（段位認定の `rank-tracks.js` と同じ考え方・同じ topic 名・同じ `allowedTopics`）。

```text
必要な知識 ＝ 元の問題の topics（PH.rankTracks.problemTopics：合同条件・根拠の理由・推論ルール・図形の性質から自動）
           ∪ 間違いに使った理由・合同条件・推論ルール・成立条件の topics（自動。例：RHA → rightTriangle、二等辺三角形の底角 → isosceles）
           ∪ バリエーションの requiredTopics（データに書いた場合）
```

コースの `allowedTopics` にすべてふくまれるバリエーションだけを、そのコースで出題する。だから、元の問題が基本でも「合同条件を直角三角形の斜辺と1つの鋭角に変えた」間違いは基本コースに入らない（テストで確認）。逆に、合同条件が SSS でも二等辺三角形・平行四辺形の性質を使う問題は総合だけになる。基本コースで出る誤りは、等式・理由・合同条件（SSS・SAS・ASA の取りちがえ）・頂点の対応・論理の順序（合同を示す前に「合同な図形の対応する辺・角」を使う）の5種類。

#### 誤りバリエーションの作り方

証明全文はコピーして持たない。Ver.1.1 と同じく、元の問題の正しい証明（`PH.buildProof`）を論理ステップに分け、**どのステップを、どう変えるか（mutation）だけ** をデータに書く（`js/error-hunt-variants.js`）。

```js
PH.ERROR_HUNT_VARIANTS = {
  'eh-p01-cong': [                // ベース問題ID（Ver.1.1 の問題ID）
    { variantId: 'e1-reason', category: 'wrongReason',
      mutation: { target: 'e1', field: 'reason', reason: 'common' },     // 根拠①の理由を「共通な辺だから」に
      // requiredTopics: [...],   // （省略可）見抜くのに、元の問題以外に必要な知識
      explain: 'AB と CB は、△ABD と △CBD が共有している辺ではなく、…' },
    { variantId: 'e2-eq', category: 'wrongEquation', mutation: { target: 'e2', field: 'body', items: ['AD', 'AB'] }, explain: '…' },
    { variantId: 'conclusion-corr', category: 'wrongCorrespondence', mutation: { target: 'conclusion', field: 'body', triangles: ['ABD', 'CDB'] }, explain: '…' },
  ],
};
```

- Ver.1.1 の30問の問題（`error-hunt-data.js` の mutation）は、各ベース問題の最初のバリエーション **`original`** として扱う。問題ID・番号・★評価の記録は Ver.1.1 のまま。
- `PH.errorVariants.def(baseId, variantId)` は、ベース問題とバリエーションを合わせた問題データを返す（`ErrorHuntGame`・`build`・`verify` にそのまま渡せる）。
- **検証**（`PH.errorVariants.verifyAll()`。全バリエーションでテスト）：Ver.1.1 の `verify`（元の問題・変えるステップがある、変わったのは1ステップだけ、種類ごとに既存の判定で本当に誤り）に加えて、同じベース問題でバリエーションIDや間違いの内容が重複しない、出題できるコースがある。
- Ver.1.2 で検証を強くした：「仮定より」の言いかえになりうる理由（中点だから・作図より・垂直な2直線がつくる角だから）は、誤りの理由に使わない（例：仮定「M は辺 BC の中点」から「中点だから BM＝CM」は正しい）。平行四辺形であることを証明する問題で、その四角形の平行四辺形の性質を使う誤り（循環論法）を「論理の順序の間違い」として確かめられるようにした（別の平行四辺形の性質を正しく使う問題は対象外）。理由のあとの補足「（AB∥DC）」は理由を変えても残す。
- 1問の誤りは1か所。間違いが後の行に影響するときは、**最初に論理がくずれる行** を正解とする（Ver.1.1 と同じ）。図の座標の上で成り立ってしまう等式・対応（対称な図など）は使わない。

#### ランダム抽選（`js/error-hunt-challenge.js`）

```text
コースを選ぶ → 出題できるベース問題を集める → 重複しない5問を選ぶ → 各問題でバリエーションを1つ選ぶ → 開始
```

1. コースで出題できるバリエーションが1つ以上あるベース問題を候補にする。
2. ベース問題を5問選ぶ（重複なし）。**総合証明は4つの単元（基本の合同証明・合同から結論を導く・三角形の性質・直角三角形・平行四辺形・特別な平行四辺形）から1問ずつ選び、残り1問は全体から**。前回のチャレンジで出たベース問題は少し出にくくする（重み 0.4）。最後に出題順をシャッフル。
3. ベース問題ごとにバリエーションを選ぶ：**前回と同じバリエーションは、ほかに候補があれば出さない**。前々回・前回に出たものは重みを下げ（0.25・0.5）、前回と同じ行（変えるステップ）が正解になるものも下げる（0.3）。同じチャレンジの中で同じ誤りの種類が重なるほど重みを下げる（0.35 倍ずつ）。
4. 候補が5問に足りなければ、あるだけ出題する（無限ループしない）。

優先順位は「数学的に正しい問題だけ（検証ずみのバリエーションだけが候補）→ ベース問題の重複なし → コースの範囲 → バリエーションの分散 → 単元・種類のバランス」。完全な均等にはしない。

**シード付き乱数**：mulberry32。チャレンジごとにシード（32ビット整数）を作り、結果に保存する。同じコース・シード・問題プール・履歴なら同じ5問になる（テストではシードと履歴を固定）。履歴（直近のバリエーション）はコースごとに別々で、じっくり練習とは混ぜない。

#### 連続PERFECT・称号システム

ランダム5問チャレンジで **100点（5問すべて正解）＝PERFECT** を続けると称号がもらえる。証明全体を読み取る正確さと、それを続ける力を評価するもので、**段位認定の段位（スピードと正確さの評価）とは完全に独立**している（名前・記録・画面を共有しない。段位名と重ならないこともテストで確認）。

- 100点で **連続PERFECT 回数** が1増える。80点以下（0〜80点）では0にもどる。途中終了・再読み込みによる中断では変わらない（結果を記録しないため）。
- 記録はコース別（基本の合同証明・総合証明で別々）：現在の連続PERFECT回数・最高連続PERFECT回数・獲得した最高称号・最高得点・挑戦回数。一方のコースの結果は、もう一方に影響しない。
- 称号は **最高連続記録から決まり、一度獲得した称号は連続が途切れても失わない**。10回で最高称号。11回以上も連続回数は数え続ける。

- **二重記録の防止**：チャレンジ1回ごとに `playId` をつけ、同じ `playId` の結果は記録しない（連続回数・挑戦回数が二重に増えない）。

### 証明パズルモード（Ver.0.3）

- 穴埋め（fill）と組み立て（build）の2形式。問題ごとに標準の形式を `puzzle.type` で指定（ステージとは別のデータ）

### 平行四辺形（Ver.0.9）

- 各問題の証明ルートは1種類（標準の成立条件）。数学的に別の成立条件で示せる場合（`alternatives`）はミスにせず案内するが、その別ルートの根拠を集めて証明することはできない（ハンターでは「今回は使わない関係」になる）。

- 等しい線分の半分（p36 の OE＝OF）は、定理のステップとして理由を選ぶだけ（1/2 の式は入力させない）。
- 段位認定の平行四辺形のミニ問題は、教材の練習プリントの図（p31・p33）と STAGE 10 の図から作るので、同じ図の問題がくり返し出ることがある。

- 新しい推論ルール（`proof-rules.js`）：同じ直線に平行な2直線は平行（`parallelTransitive`）、同じ辺に等しい2つの辺は等しい（`equalTransitive`）、等しい線分から等しい線分をひいた残りは等しい（`segmentSubtraction`。ひく線分の等しさは仮定）、錯角が等しいから平行（`alternateAnglesParallel`。p35 の後半のステップ）。平行四辺形の根拠の `fromFinal`（合同から導いた結論そのもの）、仮定の垂線の直角どうしによる錯角（p42。角の等しさを別に証明しなくてよい）。
- 数学的な検証（`npm test`）：証明する四角形が単純な凸四角形か、結論の表記、根拠が図で選べて図の上で成り立つか、仮定の根拠は仮定に書かれているか、性質の根拠は仮定の平行四辺形の性質か（証明する四角形の性質を先に使っていないか。STAGE 9 の合同の根拠もふくむ）、平行を導く根拠の角が本当に錯角・同位角で、その等しさが合同の結論・ステップ・仮定の垂線で言えるか、根拠の組から導いた条件が1つだけで `condition` と一致するか、新しいルールのステップが図と仮定から成り立つか、ヒント、ダミーのカード。

- p48 の図には作図のコンパスの跡（Oを中心とする円の弧、Q・Rを中心とする円の弧）をかき（`figure.compassArcs`：`{ center, through, around, pad }`。中心・通る点・弧をかく方向の点・広げる角度。タップには反応しない）、実際の作図ではひかない PQ・PR は破線（`figure.dashed`）にした。OP は P の先までのばしてかく（`figure.rays`）。

- p49 のように頂点（D）を通る長い辺（OA）がある図で、その頂点の角の操作領域がつぶれないようにした（`geometry.js` の `rayClearance` で、頂点そのものでの交わりを数えない）。

## 8. 技術構成

- HTML5 / CSS3 / JavaScript（ES2015程度、フレームワーク・ビルドなし）
- SVG（辺・角ごとに操作領域を持つ）
- LocalStorage（キー：`proofHunter.v1`）
- Web Audio API（効果音）
- テスト：Node.js 組み込みのテストランナー（`node:test`、追加パッケージ不要）

## 10. 問題データの構造

`js/problems.js` の `PH.problems` に問題を1件ずつ書く。ハンターとパズルは**同じ問題ID・同じ正解データ**（`evidence`・`congruence`）を参照し、パズル専用には `puzzle`（形式とダミーカード）だけを持つ。判定・描画・ヒント・証明文はすべて共通処理がこのデータを参照するので、問題ごとの if 文は不要。配列はステージ順に並べ替えられる（同じステージ内は書いた順）。

```js
{
  id: 'p16',                     // 一意なID（URL #/play/p16、#/puzzle/play/p16 に使われる）
  number: '16',
  title: '〇〇を見つけろ！',
  difficulty: 2,                 // 1〜3
  stage: 5,                      // 所属ステージ（PH.STAGES の id）
  statement: '…であることを証明しよう。',
  given: ['AB＝DC', '∠ABC＝∠DCB'],  // 仮定（表示用）
  conclusion: '△ABC≡△DCB',      // triangles と同じ順番で書く（検証される）
  // 対応順に並べた2つの三角形（同じ位置の頂点どうしが対応）
  triangles: [['A', 'B', 'C'], ['D', 'C', 'B']],
  figure: {
    viewBox: [0, 0, 400, 400],
    points: { A: { x: 80, y: 60, label: [-16, -16] }, ... },  // label: 文字の位置（点からのずれ）
    lines: [['A', 'O', 'C']],    // 3点以上が一直線上に並ぶ線（角の同一性判定に必須。並び順も検証される）
    segments: ['AB', 'BC', { name: 'AC', hit: ['O', 'C'] }, ...],
                                 // 描画・選択できる辺。途中に点がある長い辺は hit でタップする部分を指定
    angles: ['ABC', ...],        // 選択できる角（真ん中が頂点、180°未満の角）
    parallel: [['A', 'D', 1], ['B', 'C', 1], ['A', 'B', 2], ['D', 'C', 2]],
                                 // 平行の矢印 [始点, 終点, 組番号]。同じ組は同じ向き。組番号の数だけ矢印を重ねる
  },
  reasons: ['given', 'common', 'vertical'],   // ハンターで表示する理由の選択肢（パズルの組み立てでは理由カードにも使う）
  evidence: [                    // 標準的な証明の順に並べる（証明文・穴埋めの行はこの順）
    { id: 'e1', items: ['AB', 'DC'], reason: 'given', label: 'AB＝DC', mark: 1 },
    { id: 'e2', items: ['∠ABC', '∠DCB'], reason: 'given', label: '∠ABC＝∠DCB', mark: 1 },
    { id: 'e3', items: ['BC', 'CB'], reason: 'common', label: 'BC＝CB', mark: 'common' },
    // 平行線の理由では parallelGroup（どの組の平行線か）と、証明文の書き方 proofReason を指定できる
    // { id: 'e2', items: ['∠BAC', '∠DCA'], reason: 'alternate', parallelGroup: 2,
    //   proofReason: 'AB∥DCより、平行線の錯角は等しいから', ... }
  ],
  extraTruths: [                 // 正しいが今回は使わない関係（その理由で答えたらミスにしない）
    { items: ['∠AOD', '∠BOC'], reason: 'vertical' },
  ],
  congruence: 'SAS',             // 'SSS' | 'SAS' | 'ASA'
  proof: { intro: '△ABCと△DCBにおいて' },
  // 証明パズル：形式とダミーカード（正解カードは evidence・congruence から自動で作る）
  puzzle: {
    type: 'build',               // Ver.0.3 の標準形式（参考情報。Ver.0.4 では解答レベルの選択が優先され、どの問題も3レベルで遊べる）
    distractors: {
      equations: ['AB＝AC', '∠ABC＝∠BAC'],   // ダミーの等式（図の上で等しくない／結論から導かれる関係だけ）
      reasons: ['vertical'],                  // 組み立てで追加するダミーの理由（PH.REASONS のキー、任意）
    },
  },
  hints: {                       // ハンター用：根拠IDごと＋'congruence' に3段階。focus は図で光らせる要素
    e1: [{ text: '…' }, { text: '…', focus: ['AB', 'DC'] }, { text: '…', focus: ['AB', 'DC'] }],
    ...
    congruence: sasHints('∠ABC', '辺ABと辺BC'),   // 共通文のヘルパー（sssHints / sasHints / asaHints）
  },
  explanation: '…',              // 完成画面の「今回のポイント」（両モード）
  learningPoints: ['…'],
}
```

結論が辺・角の等しさの問題（Ver.0.5）は、上に次を加える（`conclusion` は最終結論の表記になる）。

```js
{
  conclusion: 'AC＝BD',          // 最終結論（finalStep.label と同じ）
  conclusionType: 'equalSide',   // 'equalSide' | 'equalAngle'（省略時は 'triangleCongruence'）
  triangles: [['A', 'O', 'C'], ['B', 'O', 'D']],   // 途中で示す合同。正解の三角形と対応の唯一の基準
  // altTriangles: [[...], [...]], // 図の対称性などで、別の対応も正解にしたいときだけ（任意）
  figure: figureOf('p02'),       // 既存の問題の図をそのまま共有できる
  finalStep: {
    relationType: 'side',        // 'side' | 'angle'
    items: ['AC', 'BD'],         // 結論の2つ（頂点の対応順どおりに書く）
    reason: 'correspondingSides',// 'correspondingSides' | 'correspondingAngles'
    label: 'AC＝BD',
  },
  puzzle: {
    type: 'build',
    distractors: {
      equations: ['AC＝BD', ...],          // 根拠のダミー（結論を入れると「まだ根拠に使えない」の練習になる）
      reasons: [],
      triangles: ['AOC/DOB', 'AOC/OBD'],   // おてがるの三角形の組のダミー（対応ちがい・組ちがい。正解にならないことを検証）
      finals: ['∠OAC＝∠OBD', 'AC＝CO'],    // 最終結論のダミー（正しいが結論ではない関係／等しくない関係）
    },
  },
  hints: {
    triangleSelection: [ ... 3段階 ... ],  // 三角形を選ぶヒント
    e1: [...], e2: [...], e3: [...], congruence: [...],
    finalStep: [ ... 3段階 ... ],          // 最終結論のヒント
  },
}
```

多段階証明の問題（Ver.0.7）は、さらに `proofSteps` を加える（従来の `evidence`・`congruence`・`finalStep` はそのまま使う）。

```js
{
  equilateral: ['ABC', 'DCE'],   // 正三角形（正三角形の辺・60° の根拠）
  proofSteps: [
    // 定理（stage 'pre'：根拠を集める前 / 'post'：最終結論のあと）
    { id: 's1', type: 'theorem', stage: 'pre', rule: 'isoscelesBaseAngles', premise: ['AB', 'AC'], premiseLabel: 'AB＝AC',
      items: ['∠ABC', '∠ACB'], label: '∠ABC＝∠ACB', short: '底角が等しい', dependsOn: [] },
    // 角の式（target ＝ parts ＝ value）
    { id: 's1', type: 'expression', rule: 'angleAddition', target: '∠ACE', parts: '∠ACD＋∠DCE', value: '∠ACD＋60°',
      premiseLabel: '△DCEは正三角形', label: '∠ACE＝∠ACD＋∠DCE＝∠ACD＋60°', short: '∠ACEの式', dependsOn: [] },
    // 式の比較（2つの角の式に依存。distractors はスタンダードの3択のダミー）
    { id: 's3', type: 'compare', dependsOn: ['s1', 's2'], items: ['∠ACE', '∠BCD'], label: '∠ACE＝∠BCD', short: '式を比べる',
      distractors: ['∠ACE＝∠ACD', '∠BCD＝∠DCE'] },
    // 後半（最終結論のあと）。dependsOn に 'final'
    { id: 's2', type: 'theorem', stage: 'post', rule: 'isoscelesConverse', premise: ['∠DBC', '∠DCB'], premiseLabel: '∠DCB＝∠DBC',
      triangle: 'DBC', label: '△DBCは二等辺三角形', short: '二等辺三角形になる', dependsOn: ['final'] },
  ],
  evidence: [
    { id: 'e1', items: ['AC', 'BC'], reason: 'equilateralSides', label: 'AC＝BC', mark: 1 },
    // 導いた事実を合同の根拠に使う（reason: 'proved' と fromStep）
    { id: 'e3', items: ['∠ACE', '∠BCD'], reason: 'proved', fromStep: 's3', label: '∠ACE＝∠BCD', mark: 1 },
  ],
  hints: { s1: [...3段階...], s2: [...], s3: [...], ... },   // ステップごとのヒント
}
```

- 結論が「〜は二等辺三角形である」の問題は `conclusionType: 'isoscelesTriangle'`。合同から導く等式を `finalStep` に、結論を後半のステップ（`isoscelesConverse`）に書く。

直角三角形の合同条件の問題（Ver.0.8）は、`congruence` を `'RHA'`・`'RHS'` にし、根拠に**直角の根拠**（`role: 'right'`）を入れる。斜辺・他の1辺・鋭角は直角の位置から自動で求めるので、データには書かない（二重に管理しない）。

```js
{
  congruence: 'RHS',                       // 'RHA'（斜辺と1つの鋭角）| 'RHS'（斜辺と他の1辺）
  given: ['四角形ABCDは正方形', '△CEFは正三角形'],
  square: ['ABCD'],                        // 正方形（頂点の順）。正方形の角・正方形の辺の根拠（仮定に「四角形ABCDは正方形」）
  equilateral: ['CEF'],
  perpendicular: [{ a: 'BD', b: 'AC', label: 'BD⊥AC' }],   // 垂直な2直線（a・b は各直線上の2点、label は仮定の書き方）
  figure: {
    ...,
    rightMarks: ['BEC', 'CDB'],            // 図にかかれている直角の印（仮定・垂線の直角だけ。正方形の角など、導く直角は書かない）
    rays: [{ from: 'A', through: 'E', extend: 34, label: 'ℓ' }],   // 直線をのばした飾りの線と名前（タップできない）
  },
  evidence: [                              // 標準の順：直角 → 斜辺 → 他の1辺／鋭角（証明文の①②③）
    { id: 'e1', role: 'right', items: ['∠CDE', '∠CBF'], reason: 'squareAngle', label: '∠CDE＝∠CBF', mark: 'right' },
    { id: 'e2', items: ['CE', 'CF'], reason: 'equilateralSides', label: 'CE＝CF', mark: 2 },   // 斜辺（直角の頂点をふくまない辺）
    { id: 'e3', items: ['CD', 'CB'], reason: 'squareSides', label: 'CD＝CB', mark: 1 },        // 他の1辺（直角の頂点をふくむ辺）
  ],
  hints: { e1: rightHints(...), e2: hypHints(...), e3: [...], congruence: rhsHints() },   // rhaHints() もある
}
```

- 直角の根拠の `label` は2つの角の等式（`∠CDE＝∠CBF`）。画面・証明文では `PH.evidenceText(ev)` で「∠CDE＝∠CBF＝90°」と表示する。印は `mark: 'right'`（直角の印）。
- 直角の理由：`given`（仮定に「∠CDE＝∠CBF＝90°」と書く）、`perpendicular`（`perpendicular` の2直線がつくる角）、`squareAngle`（`square` の角）。`perpendicular`・`squareAngle` は `rightOnly`（直角の欄だけで選ぶ理由）。
- 角の式のステップに `rule: 'triangleAngleSum'`（三角形の内角の和。`parts: '180°－∠ADB－∠DAB'`）を使える。`note` はハンターのステップの前置き（例「△ABDの内角の和は180°、∠ADB＝90°」）。数に置きかえる角は、正三角形の角（60°）と、仮定の「∠BAC＝90°」・直角の根拠の角（90°）だけ。
- データの検証（`right-triangle.verify`）：直角の根拠が1つで図の上で90°か、対応する角か、理由が図と仮定から言えるか、根拠の役割が合同条件と合うか、正方形・垂直のデータが図と合うか、図の直角の印が仮定・垂直から分かる角だけか。
- 理由 `isoscelesBaseAngles`・`equilateralSides`・`proved`（導いた等式より）を `PH.REASONS` に追加した（`proved` は段位認定の誤答の理由には使わない）。

- `proof.intro`（「△AOCと△BODにおいて」）は完成した証明で使う。STEP 1 の答えなので、問題文（`statement`）には証明する三角形を書かない。
- 理由 `correspondingSides`・`correspondingAngles`（`finalOnly: true`）は最終結論の段階だけで使う。根拠の段階の選択肢には出ない。
- 三角形の候補は図から自動で作る（`geometry.figureTriangles`：3辺がすべてかかれていて、一直線上にない3点）。図にかかれていない三角形は候補にならない。

ポイント：

- `items` の書き方：辺は `'AB'`、角は `'∠ABC'`。`AB`/`BA`、`∠ABC`/`∠CBA`、一直線上の別名（Oが AC 上なら `∠BAO`＝`∠BAC`）は自動で同一視される。
- 角の名前は必ず3文字。角は「頂点＋2本の半直線」で識別するので、一直線上に3点以上ある線は `figure.lines` に必ず書く。
- 「結論から導かれる関係」（対応する辺・角のうち根拠でないもの）は `triangles` から自動で判定されるので登録不要。ただし、結論を使わずに言える正しい関係（対頂角・錯角など）は `extraTruths` に登録して、ミスにならないようにする。
- ステージを追加する場合は `PH.STAGES` に `{ id, title, theme }` を追加する。
- 理由のID：`given`（仮定より）、`common`（共通な辺より）、`commonAngle`（共通な角より）、`vertical`（対頂角より）、`alternate`（平行線の錯角より）、`corresponding`（平行線の同位角より）。かっこ内はハンターの理由ボタンの文言で、証明文とパズルの理由カードでは「共通な辺だから」「対頂角は等しいから」などの標準的な書き方（`proof`）を使う。同じ要素を2つ選んだときは、`common`／`commonAngle` がハンターの選択肢に自動で追加される。新しい理由は `PH.REASONS` に `label`（選択肢）・`short`（スロット）・`proof`（証明文）を追加する。

### 平行四辺形の問題のデータ（Ver.0.9）

三角形の合同のデータ（`evidence`・`congruence`・`finalStep`）を平行四辺形に無理に当てはめず、**平行四辺形の部分は `parallelogram` に分けて書く**。三角形の合同の部分がない問題は `triangles`・`congruence` を持たず、`evidence: []`。

```js
{
  id: 'p34', stage: 9,
  conclusion: '四角形ABCDは平行四辺形',
  conclusionType: 'parallelogram',            // 結論の種類（PH.isQuadProblem）
  targetQuadrilateral: ['A', 'B', 'C', 'D'],  // 証明する四角形（周に沿った順）
  given: ['AD∥BC', 'AD＝BC'],
  figure: { ..., parallel: [['A', 'D', 1], ['B', 'C', 1]] },
  reasons: [], evidence: [],                  // 三角形の合同の部分はない
  parallelogram: {
    intro: ['四角形ABCDにおいて'],            // 証明文の書き出し（p33 は「対角線ACとBDの交点をOとする。」も）
    reasons: ['given', 'parallelogramSides', 'parallelogramParallel'],   // ハンターの理由の選択肢（性質はダミーとしても使う）
    evidence: [                               // 平行四辺形の根拠（数は問題ごと。STAGE 10 は2つ）
      { id: 'q1', items: ['AD', 'BC'], rel: 'parallel', reason: 'given', label: 'AD∥BC', mark: 1 },   // 平行の関係
      { id: 'q2', items: ['AD', 'BC'], reason: 'given', label: 'AD＝BC', mark: 1 },
    ],
    condition: 'PP_PARALLEL_EQUAL_PAIR',      // 成立条件（根拠の組から導いた条件と一致することを npm test で確認）
    alternatives: [],                         // ほかの道すじで示せる成立条件（選んでもミスにしない。仮定から言えることを確認）
    distractors: { equations: ['AB∥DC', 'AB＝DC', 'AD＝AB'], reasons: [] },   // パズルのダミー（証明する四角形の性質も可）
  },
  hints: { q1: [...3段階], q2: [...], pcondition: [...3段階] },
}
```

- 平行を導く根拠：`{ items: ['AD', 'BC'], rel: 'parallel', reason: 'alternateConverse', via: ['∠ADB', '∠CBD'] }`（`via` の角の等しさは、合同から導いた結論（`finalStep`）かステップの結論であること）。
- 仮定の平行四辺形（p36）：`knownParallelograms: [['A','B','C','D']]`（仮定に「四角形ABCDは平行四辺形」）。その性質を使う根拠・ステップ（`{ type: 'theorem', rule: 'parallelogramDiagonalsBisect', quad: 'ABCD', items: ['OB','OD'] }`）が書ける。中点は `midpoints: [{ point: 'E', of: 'OB' }]`、等しい線分の半分は `rule: 'halfSegments'`。ステップの `lead`（書き出し）・`proofText`（証明文の理由。`{s1}` はそのステップの番号）。
- p42 のように三角形の合同の部分がある問題は、従来の `triangles`・`evidence`・`congruence`・`finalStep` も書く（`PH.hasLemma`）。ハンター・パズルとも、合同の部分のあとに平行四辺形の部分へ進む。合同から導いた結論そのものを根拠にするときは `{ reason: 'correspondingSides', fromFinal: true }`。
- 平行の関係を結論にするステップは `rel: 'parallel'`（p40 の AD∥BC など）。同じ直線に平行・同じ辺に等しい推論は `rule: 'parallelTransitive' / 'equalTransitive'`（`dependsOn` の2つのステップ）、線分の差は `rule: 'segmentSubtraction', premise: ['AB','DC'], subtract: ['AE','FC']`。
- STAGE 9 のように、仮定の平行四辺形の性質を三角形の合同の根拠に使う問題は、`knownParallelograms` を書き、根拠の `reason` に `parallelogramSides`・`parallelogramDiagonals` などを使う（錯角は従来の `alternate`。図に平行の印を書く）。

### ひし形・長方形の問題のデータ（Ver.1.0）

平行四辺形の問題と同じ形で、四角形の部分を `parallelogram` に書く（名前は Ver.0.9 のまま）。

```js
{
  id: 'p44', stage: 11,
  given: ['四角形ABCDは平行四辺形', 'AB＝AD'],
  conclusion: '四角形ABCDはひし形',
  conclusionType: 'rhombus',                  // 'rhombus' / 'rectangle'（PH.isQuadProblem・PH.quadType）
  targetQuadrilateral: ['A', 'B', 'C', 'D'],
  knownParallelograms: [['A', 'B', 'C', 'D']], // 証明する四角形は、仮定で平行四辺形（平行四辺形の性質が使える）
  parallelogram: {
    intro: ['平行四辺形ABCDにおいて'],
    reasons: ['given', 'parallelogramSides', 'parallelogramAngles', 'rhombusSides'],   // ひし形の性質はダミー（証明前には使えない）
    evidence: [ { id: 'q1', items: ['AB', 'CD'], reason: 'parallelogramSides', label: 'AB＝CD', mark: 1 }, ... ],
    condition: 'rhombusDefinition',           // PH.SPECIAL_CONDITIONS の条件ID
    alternatives: [],
    choices: ['rhombusDefinition', 'rectangleDefinition', 'squareDefinition'],   // 成立条件の選択肢（4つの辺／4つの角／4つの辺と角がすべて等しい）
    chain: 'AB＝BC＝CD＝DA',                   // 「すべて等しい」の確認の表示（入力させない）
    distractors: { equations: ['AB＝BC', 'AC＝BD', '∠DAB＝∠ABC'], reasons: [] },
  },
}
```

- 仮定でひし形の問題（p43）は、仮定に「四角形ABCDはひし形」と書けば、ひし形（と平行四辺形）として扱われる（`specialQuad.knownQuads`）。根拠の理由に `rhombusSides`・`rhombusAngles` が使える（`alsoReasons: ['parallelogramAngles']` でほかの正しい理由も認める）。
- 「∠A＝90°」のような四角形の角の仮定は、証明する四角形の角（∠DAB）として読む。中点の理由 `midpoint`・角の二等分線などのルールは実装済み（現在の問題では使っていない）。
- `npm test` で、結論の種類と成立条件の種類が合うか、証明する四角形が仮定で平行四辺形か、図が結論の種類の図形に描かれているか、根拠から条件が導けるか、根拠を1つ減らすと導けないか、ほかの道すじの条件が仮定から言えるかを確かめる。

### 証明パズルのカードの作り方（puzzle.js）

- **等式カード**（おてがる・スタンダード）：`evidence` の `label` と `puzzle.distractors.equations`。チャレンジでは等式カードを作らず、入力した等式を同じ形（要素キー・等式キー）に変換して判定する。同じ関係（左右の入れかえ・別表記）は1枚にまとめる。並び順は問題IDから決まる（毎回同じ）。
- **理由カード**（組み立てのみ）：各根拠の理由（`proofReason` があればその書き方）と、`reasons`・`distractors.reasons` の理由。根拠専用の書き方がある理由は、一般的な書き方を重ねて出さない。
- **合同条件カード**：3つの合同条件（直角三角形の問題は5つ：`PH.conditionOrder(problem)`）。
- **直角の行**（Ver.0.8）：等式は表示済み（`rowEq`）。スタンダード・チャレンジでは、直角である理由のカード（`rreason`）を選ぶ。直角の等式は等式カードに出さず、直角専用の理由は通常の理由カードに出さない。
- **理由の判定**：理由のIDが同じなら正解。ただし根拠専用の書き方のカード（例「AD∥BCより、平行線の錯角は等しいから」）は、その書き方を使う根拠にだけ当てはまる（平行線が2組ある問題で、どちらの平行線かを区別する）。

### 問題・パズルの追加手順

1. 図の座標を、仮定と結論が成り立つように決める（2つの三角形は実際に合同に描く）。
2. 上の形式でデータを追加する（`puzzle` も忘れずに）。
3. `npm test` を実行する。`verifyAll` / `verifyProblem` が次を検出する。
   - 図にない・選択できない要素、理由が選択肢にない、ヒント・解説・ステージの不足、問題IDの重複、問題のないステージ
   - 結論の表記と `triangles` の対応順の不一致、つぶれた三角形、`lines` の点が一直線上にない
   - **図の座標で測ると等しくない根拠・`extraTruths`**、**図の2つの三角形が合同に描かれていない**、平行の印が平行でない
   - 根拠の組から導いた合同条件と `congruence` の不一致
   - **パズル**：`puzzle.type` が無効、**ダミーの等式が正しい関係（根拠・extraTruths）になっている**、ダミーが図の上で等しく見える（まぎらわしい）、未定義のダミーの理由
   - 角の操作領域どうしの重なり（`v02.test.js`）、全問題のパズルの判定（`v03.test.js`）
   - **Ver.0.7**：`proofSteps` のIDの重複・依存先・循環参照、ルールが図と仮定から成り立つか、角の式が図の上で成り立つか、式の比較の右辺が同じか・結論が導けるか・ダミーが正解にならないか、導いた事実を使う根拠が一致するか、最後の結論まで到達できるか、ステップのヒント
   - **Ver.0.5**：`conclusionType` が有効か、最終結論が途中の合同の対応する辺・角か（頂点の対応順どおりか・図の上で等しいか）、最終結論が根拠・仮定・`extraTruths` にふくまれていないか、`finalStep` の理由と種類、証明する三角形が図の上にあるか、三角形の組・最終結論のダミーが正解にならないか、`triangleSelection`・`finalStep` のヒント
4. ブラウザで実際に両モードをプレイし、タップのしやすさ・カードの分かりやすさを確認する。

### 証明の間違い探しの問題データ（Ver.1.1）

証明全文はコピーして持たない。`js/error-hunt-data.js` の各問題は、元の問題（`source`）と、1つのステップだけを変える `mutation` を持つ。`js/error-hunt-generator.js` が `PH.buildProof(元の問題)` の正しい証明を論理ステップに分け、指定したステップだけを変える（元の問題データは変更しない。証明全文への無差別な文字列置換・問題IDごとの if 文はしない）。

```js
{
  id: 'eh-p01-cong',             // 安定したID（記録・URL #/error/play/eh-p01-cong）
  no: '01',                      // 生徒に見せる番号
  unit: 'basic',                 // basic / conclusion / triangle / quadrilateral
  source: 'p01',                 // 元の問題（図・仮定・結論・正しい証明はここから）
  category: 'wrongCongruence',   // 誤りの種類（PH.errorHunt.CATEGORIES）
  difficulty: 1,
  mutation: { target: 'condition', field: 'condition', condition: 'SAS' },
  explain: 'AB＝CB、AD＝CD、BD＝BD は、どれも辺の等しさだね。…',   // なぜ間違いか
  // hint: '…'                   // 書けば、誤りの種類のヒントの代わりに使う
}
```

- `mutation.field`：`reason`（`reason`：理由ID。根拠の行は「AB∥CDより、」などの前置きを残して理由だけ変える／`rule`：推論ルールID。ステップ・後半のステップの理由の文を差しかえる）、`body`（`items`：等式／`value`：角の式の□／`triangles`：合同の三角形）、`condition`（`condition`：合同条件・成立条件のID／`text`：成立条件ではない文）。
- `PH.errorHunt.build(def)` は `{ steps（間違いを1つふくむ）, correctSteps, target（正解の行のID）, wrong, right }` を返す。正誤判定は、選んだ行のIDと `target` を比べるだけ。
- `PH.errorHunt.verify(def)`：元の問題があるか、変えるステップがあるか、文が変わったか、変わったのは1つのステップだけか（ほかのステップは正しい証明のまま）、誤りの種類ごとに本当に誤りか（4-13 の表）。`npm test` で30問すべてを確かめる。直せば正しい証明にもどる（変えたステップを元にもどすと `correctSteps` と一致）。
- 機械的に確かめられない部分（解説の文・ヒントが正解の行を直接教えないこと・読みやすさ）は目視で確認した。

  - 未挑戦（`best: null`、`playCount: 0`）と、10級（0問）で認定された記録（`best.rankName: '10級'`）は区別する。
  - `PH.storage.getRank(track)`・`recordRank(result, track)`（`track` を省略すると結果の `track`、それもなければ基本の合同証明）、`getRankLegacy()`。
- Ver.0.6 で `rankCertification` を追加（Ver.0.5 までのデータには無いので「未認定」から始まる。ハンター・パズルの記録は変わらない）。
  - 最高記録は同じ認定基準（`criteriaVersion`）の中で比べる。基準を変えたあとの最初の記録で、それまでの最高記録は `previous` に移して残す（過去の認定段位が設定変更で変わらない）。
  - 過去の全挑戦の履歴は保存しない（直近1回分の結果と誤答だけ）。個人情報は保存しない。壊れた値は「未認定」として読む。

### Ver.0.3 の記録の移行

- 読みこみ時に1回だけ、`puzzleProblems` のクリア済みの記録を、Ver.0.3 での形式に応じて移す：**穴埋め → おてがる、組み立て → スタンダード**。チャレンジはすべて未クリアから始まる。未クリアの記録は移さない（過去にプレイしていない形式をクリア済みにしない）。
- Ver.0.3 の形式は `storage.js` に固定した表（`V03_TYPES`）で判定する。`problems.js` の `puzzle.type` を後で変えても、過去の記録が別のレベルへ移ることはない。
- 移行ずみの印（`puzzleMigrated`）を保存するので、何度読みこんでも二重に移行しない。移行先にすでに記録があれば上書きしない。
- 元の `puzzleProblems` は消さない。ハンターの記録（`problems`）は変更しない。
- 復習対象：`cleared` が false、または `bestStars` が3未満の問題（★★★は対象外）。
- 壊れた値は安全な値（未クリア・★0・記録なし）として読む。過去のプレイ内容は推測で補わない。
- LocalStorage が使えない環境ではメモリ上だけで動作する（画面を閉じると消える）。

- ローカルサーバーで開く場合（どれか1つ）：
  ```sh
  npm start                      # npx http-server（初回はダウンロードあり）→ http://localhost:8080
  python -m http.server 8080     # Python がある場合
  ```
- テスト（Node.js 18以上）：
  ```sh
  npm test                       # = node --test tests/*.test.js
  ```

## 13. GitHub Pages公開方法

1. このフォルダをGitHubリポジトリにpushする（`index.html` がリポジトリ直下になるように）。
2. リポジトリの **Settings → Pages** を開く。
3. **Source** を「Deploy from a branch」、Branch を `main`、フォルダを `/ (root)` にして Save。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。

ビルド工程は不要。相対パスのみを使っているので、サブパスでもそのまま動作する。

## 15. 既知の制約事項

### 両モード共通

- 各問題の証明ルートは1種類のみ。パズルのカードは登録した証明ルートの根拠と、正しい関係にならないダミーだけで作っているため、別ルートの正しい根拠がカードとして出ることはない。
- プレイ途中で画面を離れると途中経過は保存されない（クリア記録と最後に挑戦した問題のみ保存）。
- ステージクリアの演出は「全問クリアがそろった瞬間」だけ表示する。古いデータで既に全問クリア済みのステージは演出なしでクリア表示になる。
- 効果音はブラウザの自動再生制限により、最初の操作の後から鳴る。
- `∥` 記号はフォントによって `//` のように見えることがある。

### 段位認定モード（Ver.0.6）

- 認定基準は暫定版。ミニ問題は現在の50問の図から作るので、同じ図の問題がくり返し出ることがある（同じ問題は、未出題の候補があるうちは出さない）。
- 「合同からの結論」の問題の数が多いが、出題はカテゴリごとに均等にしているので、出題数は偏らない。証明する三角形（F）は5問しかないので、11問目以降にほかのカテゴリより早く出つくす。
- 記号入力の問題は、等しい辺・角（A）、合同からの結論（E）、証明する三角形（F。5問）だけ。記号入力の割合（約60%）は、チャレンジゾーンの問題数が少ないと上下する。
- 途中で別の画面へ移ったとき（ブラウザの「戻る」など）は確認を出さずに挑戦を終え、記録しない（「やめる」ボタンでは確認する）。
- 時刻は端末の時計（`performance.now()`）で測る。端末をスリープしたときの扱いはブラウザによって異なるが、戻ったときに経過時間で判定する。
- 図を表示する問題でも、図の見た目（長さ・角度）では答えが決まらないように作っているが、図の上で等しく見える辺・角は避けきれない場合がある（正解は数学的な関係で判定する）。

### 証明の間違い探し（Ver.1.1）

- 判定は行（論理ステップ）単位。行の中のどの部分（理由か等式か）がまちがっているかは答えさせない（正解画面で表示する）。
- 等式・三角形の名前を変えた問題では、後の行（合同条件など）もそのままでは導けなくなる。「最初に論理がくずれる行」を正解とする方針で、正解の行は1つに決める。
- 元の問題の証明ルートは1種類なので、別の正しい書き方（例：別の理由でも言える等式）を正しいと認める問題は作っていない（`verify` で、変えた内容が別の理由でも正しくならないことを確かめている）。
- ヒントは誤りの種類ごとの1段階だけ。ヒントを使うと最高★★。
- 「つづきから」には間違い探しをふくめない。

### ランダム5問チャレンジ・誤りバリエーション（Ver.1.2）

- チャレンジの途中経過は保存しない。再読み込み・ほかの画面への移動・ブラウザの「戻る」で、その挑戦は終わる（記録は残らない）。
- じっくり練習のバリエーションの履歴はメモリ上だけ（再読み込みすると、直前と同じバリエーションが出ることがある）。
- 平行四辺形の単元のベース問題のうち4問（p31・p33・p44・p45）は3通り。p44（ひし形）・p45（長方形）の図では4辺・4つの角が実際に等しいので、辺・角の等式の間違いは作れない（図の上で成り立つ等式は誤りにしない）。
- 基本コースの論理の順序の間違いは5通り（「合同な図形の対応する辺・角」の先取り）。誤りの種類の割合は完全には均等でない（候補のある種類だけ出題し、重なりは重みで減らす）。
- 総合コースで、前回と同じベース問題が続けて出ることはある（重みを下げるだけ）。その場合も、ほかに候補があれば前回とちがうバリエーションを出す。
- 開発者用の確認画面（`#/error/dev`）は URL を知っていれば生徒も開ける（答えが表示される）。
- 連続PERFECT・称号は端末のブラウザ（LocalStorage）にだけ保存する。ほかの端末・ブラウザとは共有しない。ベース問題が5問未満のコースでは100点にならない（現在は両コースとも5問以上）。

### 特別な平行四辺形（Ver.1.0）

- 各問題の証明ルートは1種類（4つの辺・角がすべて等しいことを導いて定義で示す）。成立条件は3択で、「平行四辺形で、1つの角が直角」などの条件は選択肢に出さない（例：p45 は「平行四辺形で1つの角が直角」で1行で示せるが、4つの角を導くルートで解く）。
- 4つの辺（角）がすべて等しいことの確認（`chain`）は、根拠がそろったら表示するだけ（入力・選択はさせない）。
- 証明する四角形の、ひし形・長方形としての性質（4辺・4つの角・対角線の等しさ）は「証明できてから使える性質」として扱う。p45 の隣り合う角どうし（∠ABC＝∠BCD など）のように、別の推論で示せる関係もこのメッセージになる。
- 対角線が垂直であることの事実（AC⊥BD）は、段位認定の分類の問題でだけ使う（ハンター・パズルの根拠にはない）。正方形を結論にする問題はない。
- 段位認定の四角形の分類の問題は選択式だけ（記号入力の問題はない）なので、チャレンジゾーン（記号入力が多い）では少なめに出る。

### 直角三角形の合同・段位認定の2コース（Ver.0.8）

- 各問題の証明ルートは1種類（教材の模範解答のルート）。直角三角形の問題で3つの合同条件を選んだときはミスにせず選び直してもらうが、3つの合同条件による別ルートの証明（例：p26 を「1組の辺とその両端の角」で示す）は採点しない。
- ハンターでは、根拠を集める欄（直角・斜辺・他の1辺／鋭角）を選んでから根拠を答える。直角専用の理由（垂直・正方形の角）は直角の欄でしか選べない。
- 「直角三角形であること」は2つの直角をまとめて1つの根拠として確かめる（直角を1つずつ確かめる操作はない）。90°の式の入力はさせない。
- 図の直角の印は、仮定・垂線の直角だけを最初から表示する（正方形の角は、直角の根拠を確かめると緑の印がつく）。
- 段位認定の出題範囲は、元の問題の topics（使う合同条件・理由・推論ルール・図形の性質）で決めるので、元の問題が二等辺三角形などを使っていれば、その問題から作ったミニ問題（例：合同からの結論）は、問い自体が基本的でも総合証明だけで出題する。
- 段位認定の旧記録（Ver.0.7まで）は表示するだけで、新しいコースの段位とは比べない。

### 多段階証明（Ver.0.7）

- 各問題の推論の順番は登録した1ルートのみ（独立したステップの順番は自由）。別の正しいルート（例：p23 で別の角の式を使う）は自動では判定しない。
- 角度式は角と定数角の和・差だけを扱う（一般の数式処理・方程式はしない）。式を入力させる問題はなく、式の比較では共通部分・比べる式・導ける等式を答える。
- ハンターでは、前のステップで導く根拠を「詳しい理由を説明する」から説明する（説明のステップと根拠の収集を同時には進めない。説明の途中で「◀ 根拠の選択にもどる」ことはできる）。証明パズルは、証明文の順（ステップの行 → 根拠の行）のまま。
- 2つの線分が交わる点の近く（例：p23 の BD と AC の交わり）をタップすると、近いほうの辺が選ばれる。交点から少し離れた所をタップする。
- STAGE 7 の図には、同じ頂点で重なる角がある（p22 の ∠MBC と ∠DBC、p23 の ∠ACE と ∠BCD など）。重なる所をタップすると「どちらを選びますか？」で選ぶ。三角形も重なる（p21 の △ABD と △ABE など）ので「どの三角形を選びますか？」で選ぶ。

### 合同から結論を導く問題（Ver.0.5）

- 証明する三角形の組と対応は、問題ごとに1通り（`triangles`。対称性などで別の対応を許すときは `altTriangles` に書く）。別の三角形の組で証明する方法は受け付けない。
- 三角形の候補は、3辺がすべて図にかかれている三角形だけ。現在の STAGE 6 の図は三角形が2つずつなので、パズルの STEP 1 は「2つの三角形と頂点の対応」を答える形になる（おてがるのダミーは対応ちがいの組）。
- ハンターの STEP 1 は、2つの三角形を選んで「決定」するだけ（入門用のモードなので、頂点の対応は答えない）。正しい組なら、頂点の対応は問題データ（`triangles`・`altTriangles`）から決まり、「三角形確認」ボタンで見られる。三角形の組がちがうときはミス1回（同じ組の再判定では増えない）。
- 最終結論で「正しいが求められた結論ではない関係」は、ハンターではミスにせず、パズルでは誤ったカードとしてミスに数える（ハンターの「今回は使わない関係」・パズルのダミーと同じ扱い）。
- チャレンジでは、最終結論の等式の対応順の誤りはミスに数えない（根拠の等式と同じ）。三角形の対応の誤りはミスに数える。

### ハンターモード

- 別ルートで正しい根拠は、`extraTruths` に登録したものは「今回は使わない関係」としてミスにしない。登録していない正しい関係のうち、結論を使わないと言えないものは「結論から導かれる関係」または「まだ言えない」として扱う。
- 2段階の推論が必要な関係（例：p04 の ∠ABD＝∠ACD、p14 の ∠BDC＝∠CEB）は、1つの理由では言えないため不正解（「まだ言えないよ」）になる。
- 角は180°未満のみ対応。選択できる角は `figure.angles` に登録したもの（隣り合う2辺でできる角）に限られ、例えば問題01の ∠ABC（∠ABD＋∠DBC）は選べない。
- 途中に点がある長い辺（p14 の AB・AC）は、点より先の部分（D〜B、E〜C）をタップするとそのまま選ばれ、A〜D・A〜E の部分をタップすると「AB／AD」「AC／AE」のどちらかを選ぶポップアップが出る。DB・EC を単独の辺として選ぶことはできない（辺として登録していないため）。
- STAGE 1〜6 の20問と STAGE 8 の6問には、ふくむ角とふくまれる角を両方とも選べる図はない（STAGE 7 にはある。重なった角は「どちらを選びますか？」で選ぶ）。STAGE 8 の図は、必要な角だけを選べるようにしている（例：p27 の ∠EBC は ∠ABC と同じ角で、その中の ∠DBC は選べない）。
- 交わる線の交点に名前がない場合（p04・p14）、交点のまわりの角は選べない。
- 印つけで生徒がつけた印と根拠の自動表示の印が同じ辺・角に重なる場合は、自動表示（緑）を優先して表示する（生徒の印は内部に残る）。
- 「ヒント」は最終段階を繰り返し表示できるが、回数は新しい段階を開いたときだけ増える（パズルも同じ）。

### 証明パズルモード

- 解答レベルは全問題共通の設定で、問題ごとに別のレベルを記憶することはしない。プレイ中にレベルを変えると、その問題は最初からやり直しになる。
- おてがる（穴埋め）では理由が表示済みのため、等式を入れかえられるのは「同じ理由の行どうし」だけ（例：p01 の ① AB＝CB と ② AD＝CD）。理由の違う行に入れると、その理由では言えない等式として不正解になる。
- ダミーの等式は問題ごとに手で指定している（自動生成はしない）。ダミーには「図の上で等しくない関係」と「結論から導かれる関係」だけを使い、`npm test` で確認している。
- 理由カードの文言は証明文の書き方（「対頂角は等しいから」など）で、ハンターの理由ボタン（「対頂角より」など）とは表記が異なる。
- 完成画面の証明文の行の順番は、生徒が組み立てた順になる（標準の順と異なることがある）。
- チャレンジでは、入力した等式が登録した証明ルートの根拠と同じ関係かで判定する（別ルートの正しい関係は、`extraTruths` に登録したものも含めて不正解になる）。図にかかれていない線分（例：p01 の AC）や、一直線上で角にならない入力（例：∠OAC で O・C が A から同じ向き）は、エラーにはならず不正解として扱う。
- チャレンジの等式欄は、辺か角かを生徒が選ぶ（どちらの等式が入るかは表示しない。最初は辺の入力欄）。∠ は「辺⇔角」で角に切りかえると自動で入る。
- 入力途中の等式は、その問題を解いている間だけ残る（画面を離れると消える）。
- Ver.0.3 の記録の移行は、クリア済みの記録だけを対象にする。
- 図につけた印は、その問題を解いている間だけ残る（画面を離れる・「もう一度」で消える。保存はしない）。完成画面の図には、根拠の印（自動表示）だけを表示する。
