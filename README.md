# 証明ハンター Ver.0.6

**図形に隠された3つの根拠を探し出せ！**

## 1. アプリ概要

中学数学の「三角形の合同の証明」を、ゲーム感覚で練習できるWebアプリ。
インストール・ログイン不要。PC・スマートフォン・タブレットのブラウザで動作する静的Webアプリ（ビルド不要、`file://` でも起動できる）。

Ver.0.3 で、これまでのゲーム（**ハンターモード**）に加えて **証明パズルモード** を追加し、
Ver.0.4 で証明パズルを **3段階の解答レベル**（おてがる → スタンダード → チャレンジ：「えらぶ」→「くみたてる」→「自分で思い出す」）にした。
Ver.0.5 で、結論が三角形の合同ではなく **辺・角の等しさ**（例：AC＝BD、∠ABC＝∠CDA）の問題を、両モード・3レベルに追加した（STAGE 6）。
「どの三角形を合同にする？」→「3つの根拠」→「合同条件」→「合同だから対応する辺・角が等しい」の順に考える。
Ver.0.6 で、第3のモード **段位認定**（120秒でミニ問題を次々に解き、10級〜皆伝の21段階で認定）を追加した。

- **ハンターモード**：図をタップして等しい辺・角とその理由を見つけ、3つの根拠を集めて合同条件を選ぶ（「根拠を見つける」）。
- **証明パズルモード**：等式・理由・合同条件のカードをタップで空欄に入れ、証明文を完成させる（「証明を組み立てる」）。
- **段位認定モード**：120秒で、証明の一部分を取り出したミニ問題に次々に答え、正解数とミス数から段位を認定する（「学んだ知識を素早く正確に使う」）。

ハンター・パズルは同じ20問・6ステージを使い、記録と評価はモードごと（パズルはさらに解答レベルごと）に別々に保存される。段位認定のミニ問題も、この20問の正解データから自動で作る（問題文や正解を別に書き写さない）。証明全文の自由記述は行わない（紙のノートでの練習を想定）。

## 2. 開発目的

- 証明を書く前段階の思考（どこが等しいか・なぜ等しいか・どの合同条件か）を、短いテンポで繰り返し練習できるようにする。
- 証明文の構成（等式と理由の対応、3つの根拠と合同条件の関係）を、選択式で無理なく身につけ、定期テストで証明を書く力への橋渡しにする。
- 数学が苦手な生徒でも、証明への心理的ハードルを下げて取り組めるようにする。
- 図形から必要な情報を見つけ、理由を考え、合同条件を判断できる力を育てる（証明文の暗記ではない）。

## 3. 対象学年

- 中学2年生（図形の合同・証明の初学者）
- 中学3年生（証明の復習）
- 証明が苦手な生徒

## 4. 3つのゲームモード

タイトル画面の3枚のカード（ハンター／証明パズル／段位認定）からモードを選ぶ。段位認定のカードはゴールド系で、「120秒チャレンジ」と最高段位（初めては「未認定」）を表示する。「つづきから」は、最後にプレイしたモードと問題を再開する（例：「証明パズル・問題04」）。

### 4-1. ハンターモードの遊び方

1. ステージを選び、問題を選ぶ（どのステージ・どの問題からでも挑戦できる）。
2. 「辺選択」なら **辺** を、「角選択」なら **角（角の内側）** を2つタップ → 等式の候補（例：`AB＝CB`）が表示される。
   辺選択では辺だけ、角選択では角だけがタップに反応するので、頂点付近でも誤選択しない。
3. **等しい理由** を選び、「根拠を確定」。等式と理由の両方が正しければ根拠スロットに登録される。
   - 共通な辺・共通な角は、同じ辺（角）を2回タップする（`BD＝BD`）。選択中の表示が赤に変わり、3回目のタップで選択解除。
4. 3つの根拠が揃ったら **合同条件** を3択から選んで「決定」。
5. 「証明成功！」→ 完成した証明文と「今回のポイント」を確認する（式・理由をタップすると図の該当部分が光る）。
6. 困ったら「ヒント」（3段階）や、図の下の「△ 三角形を確認」（対象の三角形と対応する頂点を表示）を使う。

### 4-2. 証明パズルモードの遊び方

1. パズルのステージ選択画面の上で **解答レベル**（おてがる／スタンダード／チャレンジ）を選ぶ（初期値はおてがる。選んだレベルは保存され、次回も同じ）。
2. 図と仮定・結論を確認する。
3. 証明文の空欄（解答欄）をタップする。画面の下に、その空欄に入るカード（等式／理由／合同条件）だけが出てくる（チャレンジの等式欄では数学キーパッドが出る）。カードをタップすると空欄に入り、カードの領域は隠れる（選択中の空欄は次の空いている空欄へ進む）。
   - 入れたカードは何度でも変えられる（空欄をもう一度タップ → 別のカード）。カードの領域の「×」で何も選ばずに閉じる。
   - 「すべてリセット」は証明文の下にあり、全部の空欄を空にする。
   - カードを入れたり変えたりするだけではミスにならない。
4. すべて埋めたら、証明文の下の「答え合わせ」。まちがえた空欄は赤くなり、理由が表示される。正しく入っているカードは残るので、赤い所だけ直して、もう一度答え合わせする。
5. すべて正しければ「証明パズル完成！」→ 完成した証明全文（式・理由をタップすると図が光る）、今回のポイント、学習のポイントを確認する。
6. 困ったら「ヒント」（3段階。未完成・不正解の部分を優先）。
7. STAGE 6（結論が辺・角の等しさ）の問題では、証明文の最初の「△＿と△＿において」と、最後の「したがって、〜から、結論」も空欄になる（→ 4-6）。
8. 図をタップすると、図が大きく表示されて**印をつけられる**（ハンターモードと同じ：辺の印1〜3本・角の印1〜2本・消す・印をすべて消す）。閉じると、つけた印が問題の図に表示される。印は下書きで、答え合わせには関係しない。

### 4-3. 3つの解答レベル

全20問を3つのレベルすべてで遊べる。★評価・クリア状況・復習はレベルごとに別々。

ただし証明パズルで★★★を取ると、同じ問題の下位の解答レベルも★★★になる（チャレンジで★★★ → おてがる・スタンダードも★★★、スタンダードで★★★ → おてがるも★★★）。結果画面で「〇〇 のこの問題も ★★★ になったよ！」と知らせる。

| レベル | 説明（ボタン） | 画面 | 生徒が答えるもの | 判定 |
|---|---|---|---|---|
| **おてがる**（穴埋め・fill） | 等式を選んで穴埋め！ | 証明文の理由（「仮定より」など）は表示済み。等式と合同条件が空欄 | 各行の等式カード（3つ）＋合同条件 | 等式が、その行に表示された理由で言える根拠か。同じ理由の行どうしなら入れかえてもよい |
| **スタンダード**（組み立て・build） | 等式と理由を組み立てよう！ | 根拠①〜③それぞれに「理由」と「等式」の空欄。最後に合同条件 | 理由カードと等式カードのセット（3組）＋合同条件 | 等式が根拠であること、理由との組み合わせ、重複がないこと。根拠の順番は自由 |
| **チャレンジ**（challenge） | 等式を自分で入力しよう！ | スタンダードと同じ形。**等式カードは出さない** | 理由カード＋**等式を数学キーパッドで入力**（3組）＋合同条件 | スタンダードと同じ。入力した等式は正規化して同じ判定にかける |

どのレベルも、合同条件は「答えた3つの根拠から導かれる条件」と一致するかで判定する。

- プレイ画面のタイトルバーに現在のレベルを表示。タップすると「解答形式を変更すると、今の解答内容はリセットされます。変更しますか？」と確認したうえで、新しいレベルで最初からやり直す（ミス・ヒント・印もリセット。保存ずみの最高評価は変わらない）。
- そのレベルの全問をクリアすると、ステージ選択画面と完成画面に案内を表示（自動でレベルは変えない）：「おてがる全問クリア！ 次はスタンダードに挑戦してみよう！」「スタンダード全問クリア！ チャレンジにも挑戦してみよう！」「証明マスターへの道をクリア！ ノートでも証明を書いてみよう！」

### 4-4. チャレンジの数学キーパッド

等式の空欄をタップすると、画面の下にキーパッドが出る（スマホ縦向きは下からのシート、スマホ横向きなど高さの低い画面は画面の下に固定したシート（選んだ空欄がシートの上に見えるようにページが動く）、PCは右側の欄の下）。

```text
┌─────────────────────────────┐
│ [辺の等式 □□＝□□] [角の等式 ∠□□□＝∠□□□] │ ← はじめにどちらかを選ぶ
│         AB＝C＿                │ ← 入力中の式（入力位置が分かる）
│  A   B   C   D   O              │ ← その問題の図にある頂点記号だけ
│  ←   消す        決定           │ ← ＝・∠ のボタンはない（入力欄に表示ずみ）
└─────────────────────────────┘
```

- 入力例：辺は「辺の等式」→ A → B → C → D → 決定 で `AB＝CD`。角は「角の等式」→ A → B → C → D → E → F → 決定 で `∠ABC＝∠DEF`。＝ と ∠ は入力欄に最初から表示されているので押す必要はなく、左辺を入力しおわると自動で右辺に進む。
- 入力ルール：辺は2文字、角は∠＋3文字。左右は同じ種類。図にない文字は押せない。同じ辺・角の中で同じ文字（AA、∠ABA など）は押せない。不完全な式は「決定」できない。
- 今押せる文字を強調する。←で1文字削除（右辺が空なら＝をまたいで左辺の最後の文字を消す）、「消す」で最初から。←・消す・決定は1行に並ぶ。「辺の等式／角の等式」で種類を切りかえると、その欄の入力はリセット。
- **三角形の入力**（Ver.0.5、STAGE 6 の「△＿と△＿において」の欄）：入力欄は `△□□□と△□□□`。種類のボタンはなく、頂点記号を6つ押して「決定」（A → B → C → D → E → F で △ABCと△DEF。1つ目を入力しおわると自動で2つ目へ）。同じ三角形の中で同じ文字は押せない。図にない三角形（一直線上の3点、かかれていない辺）や同じ三角形を2つ入力したときは、理由を赤く表示して決定できない。頂点の対応は、入力した2つの三角形の頂点の順番から判定する（文字列の一致ではない）。
- 入力途中の式は空欄ごとに残る（別の空欄に移っても、図を開いて印をつけても消えない。図のウィンドウを閉じるとキーパッドに戻る）。決定すると空欄に入り、キーパッドは隠れて次の空欄へ進む。
- PCのキーボード：A〜Z（頂点記号）、Backspace、Enter（決定）、Esc（閉じる）。`=` は押しても押さなくてもよく、`<` は角の等式に切りかえる。正しい形式の等式なら貼り付けもできる（三角形の欄は `ABC/DEF`・`ABCとDEF`・`ABC,DEF` など）。
- 正規化：小文字→大文字、全角・半角の英字と＝の同一視、空白の除去。数学的な同一性（AB＝CD と CD＝AB、AB と BA、∠ABC と ∠CBA、一直線上の点による角の別名）は既存の `geometry.js`・`validation.js` で判定する。
- **頂点の対応順**：チャレンジでは、根拠として正しい等式でも、2つの三角形の頂点の対応順に合った書き方でなければ正解にしない（`validation.correspondenceOrder`）。左辺を一方の三角形の頂点で読み、対応で移したものが右辺と文字の順番まで一致すればよい。
  - 例（p01 △ABD≡△CBD、A↔C・B↔B・D↔D）：AB＝CB、BA＝BC、CB＝AB は正解。AB＝BC、共通な辺の BD＝DB は「対応順が合っていないよ」。
  - 角は一直線上の別名を三角形の頂点に読みかえて確かめる（p03 で ∠BAC＝∠DCA は正解、∠CAB＝∠DCA は対応順の誤り）。
  - 対応順の誤りはミスに数えない（理由の誤りが同時にあれば、理由の誤りだけミス）。おてがる・スタンダードのカードは正しい対応順で書かれているので影響しない。
- 正誤は「答え合わせ」で判定する（入力中には判定しない）。チャレンジの判定メッセージ：

| 状況 | メッセージ |
|---|---|
| 等式が誤り | その2つが等しいと言えるか、図と仮定を確認しよう。 |
| 理由だけ誤り | 等式は合っているよ！ 理由をもう一度考えてみよう。 |
| 根拠が重複 | 同じ根拠が2回使われているよ！ |
| 結論から導く関係 | それは合同が証明できてから使える関係だよ！ |
| 合同条件が誤り | 3つの根拠と合同条件の関係を確認しよう。 |
| 頂点の対応順が合っていない（例：p01 で AB＝BC） | 対応順が合っていないよ！ 結論 △…≡△… の頂点の順番に合わせて書こう。（**正解にしないが、ミスにも数えない**） |
| 等式が未完成 | （決定できないので空欄のまま。「答え合わせ（あとnか所）」と表示） |

- チャレンジのヒント：1段階目は考え方、2段階目は図の該当部分を光らせる、3段階目は正しい等式を表示（自動では入力しない。自分で入力する）。

### 4-5. 評価（両モード共通）

★★★ ミス0・ヒント0 ／ ★★ ミス2回以内かつヒント1回以内 ／ ★ その他。

- ハンター：誤った等式・理由・合同条件を確定するとミス1回。
- パズル：答え合わせのとき、誤りのある根拠の組・合同条件ごとにミス1回。**同じ誤りのまま答え合わせをくり返してもミスは増えない**（別の誤ったカードに変えると、そのぶん増える）。
- STAGE 6：三角形の誤り（組・対応）、最終結論の等式・理由の誤りも、それぞれミス1回（同じ誤答の再判定では増えない）。

### 4-6. 合同から結論を導く問題（Ver.0.5、STAGE 6）

結論の種類（`conclusionType`）は3つ。p01〜p15 は従来どおり三角形の合同で、手順も変わらない。

| 種類 | ID | 例 | 問題 |
|---|---|---|---|
| 三角形の合同 | `triangleCongruence`（省略時） | △ABC≡△DEF | p01〜p15 |
| 辺の等しさ | `equalSide` | AC＝BD | p17・p18・p19 |
| 角の等しさ | `equalAngle` | ∠ABC＝∠CDA | p16・p20 |

辺・角の等しさの問題は、次の4段階で進む。**合同が成立した時点ではクリアにならず、STEP 4 まで正解して「証明成功！」になる。**

1. **三角形を選ぶ**：「どの2つの三角形を合同にすればよい？」→「△＿と△＿において」を完成させる（頂点の対応もふくむ）。
2. **3つの根拠**：従来と同じ。最終結論や、まだ証明していない合同から言える関係（対応する辺・角）は根拠に使えない。
3. **合同条件**：正しければ「合同成立！ あと一歩で証明完成！」と表示し、2つの三角形を色分けする。
4. **結論を導く**：結論の2つの辺（角）を選び、理由「合同な図形の対応する辺（角）は等しい」を選ぶ。

**ハンターモードの操作**

- STEP 1 は「△ 三角形の内側をタップ」モードで始まる（辺選択・角選択はできない。印つけはできる）。1つ目の三角形は青、2つ目は黄で表示。選んだ三角形をもう一度タップで解除、3つ目をタップすると2つ目と入れかわる。重なった三角形をタップしたときは「どの三角形を選びますか？」で選ぶ（候補は図にかかれた三角形だけ）。
- 2つ選ぶと、1つ目の三角形の頂点（アルファベット順）ごとに、対応する2つ目の頂点をボタンで順に押す（`A↔C B↔B D↔D` のように表示）。「←」（1つもどす）「消す」（選んだ三角形をすべて消す）「決定」（赤）。
- パネルの上に手順（①三角形 ②根拠 ③合同条件 ④結論）を表示する。
- STEP 4 の理由の選択肢：仮定より・問題の理由（対頂角など）・合同な図形の対応する辺より・合同な図形の対応する角より。ボタンは「証明を完成する」。
- 図の下のボタンは、STEP 1 の間は「△ 三角形を探すヒント」（正しい三角形は見せず、「結論の辺ACは、どの三角形にふくまれているかな？」などを表示し、結論の辺・角を光らせる）。STEP 1 が正解したあとは従来の「△ 三角形を確認」。

**証明パズルの3レベル**

| レベル | 三角形（最初） | 根拠・合同条件 | 最終結論（最後） |
|---|---|---|---|
| おてがる | 「△ABDと△CBD」のような三角形の組を3択（ダミーは対応ちがい） | 既存の穴埋め | 理由「合同な図形の対応する辺（角）は等しいから」は表示済み。結論の等式を3択から選ぶ |
| スタンダード | 1つ目の三角形のカード（図の三角形）＋2つ目の三角形のカード（頂点の並び6通り。並びが対応を表す。1つ目と同じ三角形は出さない） | 既存の組み立て | 理由カード（対応する辺／対応する角／仮定）＋結論の等式カード |
| チャレンジ | キーパッドで三角形を入力（△□□□と△□□□） | 既存のチャレンジ | 理由カード＋結論の等式をキーパッドで入力 |

- 合同の行（「…ので、△＿≡△＿」）は、生徒が答えた三角形で表示する（STEP 1 の答えは見せない）。答え合わせのメッセージにも、証明する三角形は書かない。
- 完成した証明は「△AOCと△BODにおいて … ので、△AOC≡△BOD / したがって、/ 合同な図形の対応する辺は等しいから、/ **AC＝BD**」の形。合同は途中の結果として小さめに、最終結論を枠つきで強調する。式・理由・結論をタップすると図が光る。

| 状況 | メッセージ | ミス |

| 三角形の組がちがう | この2つの三角形で、結論を導けるかな？ 対応する辺・角に注目しよう！ | ○ |
| 同じ三角形を2つ選んだ（ハンター） | 同じ三角形を2つ選んでいるよ。ちがう2つの三角形を選ぼう！ | × |
| 未完成（ハンター） | （「決定」を押せない。「2つの三角形と、対応する頂点を決めよう」の案内） | × |
| 結論の等式は正しいが理由がちがう | 等しい辺（角）は選べたね！ 合同な図形の性質を使って、理由をもう一度考えよう。（パズル：合同な図形の性質を使おう。辺と角のどちらの等しさかな？） | ○ |
| 合同から言える正しい関係だが、求められた結論ではない | 正しい関係だけれど、問題で求められている結論ではないよ。結論をもう一度確認しよう！ | ハンター×（やわらかい音）／パズル○ |
| 合同を示すのに使った根拠を結論にした | それは合同を示すのに使った関係だよ。合同から導く結論を選ぼう！ | ○ |
| 等しくない | その2つは、合同な三角形で対応しているかな？ 結論をもう一度確認しよう！ | ○ |
| チャレンジで結論の対応順が合っていない（例 p17 で CA＝BD） | 対応順が合っていないよ！ 2つの三角形の頂点の対応に合わせて書こう。 | × |

**ヒント**（3段階。新しい段階を開いたときだけ回数が増え、★評価に反映。最終段階でも答えは自動で入れない）

- 三角形の選択：①「結論の辺・角は、どの三角形にふくまれているかな？」②「結論で等しいと示したい2つの辺・角を、別々の三角形に見つけよう！」（結論の辺・角を光らせる）③ 合同にする三角形の候補と対応する頂点を表示（自動では確定しない）。
- 最終結論：①「合同な三角形で、対応する辺や角にはどんな性質があるかな？」②「結論の…を、合同な三角形の対応関係で確認しよう！」③「合同な図形の対応する辺（角）は等しい、という性質を使おう！」
- ヒントの対象は、三角形 → 根拠 → 合同条件 → 最終結論 の順（パズルは、まだ正しくない所を優先）。

### 4-7. 段位認定モード（Ver.0.6）

**基本ルール**

- 制限時間は **120秒**（固定）。時間内に解ける問題数は無制限。開始前に「3・2・1・START！」を表示し、STARTと同時に計測を始める。
- 1問の解答箇所は1〜3か所（目安：1か所70%・2か所25%・3か所5%）。**何か所あっても、すべて正しいときだけ1問正解**（部分点なし）。
- **1〜10問目：セレクトゾーン**（すべて選択式・3択）。1か所の問題は選択肢をタップした時点で判定、2〜3か所の問題はすべて選んで「決定」（赤）。序盤（1〜3問目）は易しい問題・解答箇所1つ、4〜10問目は解答箇所2つまで。
- **11問目〜：チャレンジゾーン**。11問目で「CHALLENGE ZONE！」を短く表示（タイマーは止めず、操作もさえぎらない）。記号入力の問題を約60%（`inputRatio`）、残りは選択式（理由・合同条件など）。
- 正解・不正解はすぐ判定し、○／× を約0.3秒表示して次の問題へ（解説は終了後の振り返りで）。
- **パス**：ミス1回として次の問題へ（正解数は増えない）。不正解後の再回答はできない。
- 一時停止はない。別タブ・端末のロック中も時間は進み、戻ったときに120秒を過ぎていれば終了する。再読み込みでは挑戦を再開しない（`#/rank/play` を直接開くとトップへ戻る）。
- 途中でやめるとき（左上の「やめる」）は「段位認定を途中で終了しますか？ 今回の記録は残りません。」と確認する。途中終了・画面の移動は記録しない。

**タイマー**

- 表示は「1:42」のような分:秒。残り30秒以下でオレンジ、10秒以下で赤（点滅はしない。10秒で短い音）。
- 残り時間は `performance.now()` と開始時刻の差から毎回計算する（`setInterval` の回数は数えない）。描画の遅れや端末の負荷で制限時間は延びない。
- 残り0で解答の受付を終える。解答途中（未選択・未入力）は正解にもミスにも数えない。解答の確定と時間切れが重なったときは、確定した時刻が120秒以内かで判定する（ちょうど120秒は時間内）。終了処理（結果の記録・結果画面への移動）は1回だけ。

**ミニ問題の種類**（`rank-questions.js` が既存20問の `evidence`・`congruence`・`triangles`・`finalStep` から生成）

| タイプ | 例 | 形式 | カテゴリ |
|---|---|---|---|
| A 等しい辺・角 | △ABDと△CBDにおいて、共通な辺だから ＿＿＿ | 選択式／記号入力（等式） | 等しい辺・角 |
| B 等しい理由 | ∠AOC＝∠BOD が等しい理由は？（2〜3か所：複数の等式の理由をまとめて） | 選択式 | 理由 |
| C 合同条件 | AB＝DE、BC＝EF、∠ABC＝∠DEF から使える合同条件は？ | 選択式 | 合同条件 |
| D 三角形の対応 | △ABC≡△DEF のとき、頂点Aに対応する頂点は？（2〜3か所：まとめて） | 選択式 | 三角形の対応 |
| E 合同からの結論 | △ABC≡△DEF より、AC＝＿＿（辺・角） | 選択式／記号入力（左辺は固定） | 合同からの結論 |
| F 証明する三角形（STAGE 6） | AC＝BD を証明するために合同を示す三角形を、頂点の対応順に | 選択式／記号入力（三角形） | 三角形の対応 |
| 結論を導く理由（STAGE 6） | △AOC≡△BOD が証明できた。したがって AC＝BD と言える理由は？ | 選択式 | 合同からの結論 |

- 生成数：**294問**（同じ内容の問題はまとめる）。等しい辺・角 39、等しい理由 69（1か所39・2か所15・3か所15）、合同条件 15、三角形の対応 101（対応する頂点72・2か所12・3か所12・証明する三角形5）、合同からの結論 70（辺30・角35・理由5）。記号入力でも出せる問題は109。
- 図が必要な問題（A・B・F）は、元の問題の図と仮定を表示する（B は等式の辺・角を強調）。合同の式から答える問題（C・D・E）は図を出さない（図の見た目から答えを推測させない）。
- 記号入力は既存の数学キーパッド（`math-keypad.js`）を使う。辺・角の種類が問題から決まるときは最初から入力形式を設定する（E は「AC＝＿＿」のように左辺を固定、F は三角形の入力）。キーパッドは段位認定用にコンパクト。

**正誤判定**

- 文字列の比較ではなく、既存の `geometry.js`・`validation.js` で判定する：辺の両端の順序、等式の左右の交換、角の逆順、一直線上の点による角の別名、三角形の頂点の対応、根拠の組と合同条件。
- **同じ数学的関係を表す正しい表記は正解**（例：p01 の共通な辺は BD＝BD・DB＝BD・BD＝DB のどれでも正解。「仮定より」で答える問題は、仮定のどちらの等式でも正解）。頂点の順序を判定するのは、問題が「頂点の対応順に」と明示する F だけ。
- 選択肢は、正解がちょうど1つになるように作る（誤答の選択肢に `extraTruths` や根拠を使わない。E の誤答は図の上でも等しくない辺・角だけ。理由の誤答は、その等式に使っても正しくならない理由だけ）。`npm test` で全問題を別の方法で確かめている。

**出題の抽選**（`rank-game.js`）

- 乱数のシードを記録し、毎回出題順と選択肢の並びが変わる（テストではシードを固定して同じ順番を再現）。
- 5つのカテゴリ（等しい辺・角／理由／合同条件／三角形の対応／合同からの結論）のうち、出題数の少ないものから選ぶ（最初の10問で5つすべてが出る）。
- 未出題の候補があるうちは同じ問題を出さない。同じ元問題が続かないようにする。候補を使い切ったら、直近の問題を避けて再利用する（候補が少なくても止まらない）。
- パスしても難易度の分布は変わらない（易しい問題だけを探すことはできない）。

**認定基準（暫定版・`rank-config.js`）**

有効正解数 ＝ max(0, 正解数 − ミス数 × 0.5)。条件を満たす最も高い段位を認定する（例：正解15・ミス4 → 13.0 → 四段）。

- 内部のランク番号（10級＝0 … 皆伝＝20）で比べ、最高段位は大きい方を残す。
- 段位・制限時間・出題割合・コンボの演出は `rank-config.js` に集約している（画面や判定に数値を直接書かない）。基準を変えるときは `criteriaVersion` を上げる。

## 6. 実装済み機能

### ハンターモード（Ver.0.1〜0.2）

- SVGによる図形描画（画面幅に合わせて拡大縮小、縦横比維持）
- 「辺選択」「角選択」モード。辺選択では辺の操作領域だけ（図が縮小表示されても画面上で約32px以上。タップした点にいちばん近い辺を選ぶ）、角選択では角の操作領域だけ（角の内側の扇形）を置く。角選択中は選べる角に点線の円弧を表示
- 重なった辺・角の選択：線分ACの上に点Bがあり AC・AB の両方が選べる場合や、∠ABC の内側に ∠ABD がある場合など、タップした場所が2つ以上の辺・角にあたるときは「どちらを選びますか？」（印つけでは「どちらに印をつけますか？」、消すでは「どちらの印を消しますか？」）のポップアップで選ぶ。長い辺・大きい角が先に並ぶ。消すときは印がついているものだけが候補。ハンターの選択・印つけ・消す、証明パズルの印つけで共通
- 印つけ（辺の印／角の印のどちらか一方を選び、その種類の要素だけに印をつける）、消す（1つずつ／すべて）、根拠登録時の自動表示の印（緑、生徒の印とは別管理）
- 同じ辺・角の2回タップで共通な辺・共通な角（選択表示が赤）。理由に「共通な辺より」／「共通な角より」が出る。「根拠を確定」「決定」ボタンは赤
- 等しい理由の選択と判定、根拠の登録（順不同）・重複防止、合同条件の3択と判定（根拠の組と三角形の対応から条件を導いて照合）
- 「正しいけれど今回は使わない関係」はミスにせず、ブザーより柔らかい効果音で知らせる
- 段階式ヒント、三角形を確認（2つの三角形の色分けと対応する頂点）
- ステージ制（5ステージ×3問。Ver.0.5 で STAGE 6 の5問を追加）、ステージクリア演出、苦手な問題の復習、証明完成後の解説（今回のポイント）、式・理由のタップで図が光る（平行線の理由なら平行線も）

### 証明パズルモード（Ver.0.3）

- 穴埋め（fill）と組み立て（build）の2形式。問題ごとに標準の形式を `puzzle.type` で指定（ステージとは別のデータ）
- タップだけで操作：空欄をタップ → 空欄の種類に合うカードだけを下に表示 → カードをタップで配置し、カードの領域は隠れる（選択は次の空欄へ進む）。配置済みの空欄をタップで選び直し、すべてリセット
- 答え合わせ：空欄ごとに正誤を判定し、誤りは赤く表示して理由を説明（「等式は合っているよ！ 理由をもう一度考えてみよう。」「この3つの根拠では、その合同条件は使えないよ！」「同じ根拠が2回使われているよ！」「それは△…≡△…が証明できたら言えることだよ！」など）。正しいカードは消さない
- 判定は既存の正規化を再利用（AB＝BA、左右の入れかえ、∠ABC＝∠CBA、一直線上の点による角の別名）。根拠の順番の入れかえ（組み立ては自由、穴埋めは同じ理由の行どうし）を正しく認める
- 平行線が2組ある問題（p10・p13）では、どちらの平行線の錯角・同位角かも区別する。一般的な理由（例「仮定より」）は、根拠専用の書き方の根拠（例「仮定より、Mは辺BCの中点だから」）にも使える
- パズル専用の3段階ヒント（未完成・不正解の部分を優先し、その空欄を選んだ状態にして図の該当部分を光らせる。カードの領域はヒントと重ならないよう閉じる）。ヒント回数はモードごとに別
- 完成画面：「証明パズル完成！」・★・ミス・ヒント、生徒が組み立てた順の証明全文（式・理由をタップすると図が光る）、今回のポイント、学習のポイント、STAGE CLEAR（パズルの記録で判定）
- パズル用のステージ選択・問題一覧・苦手な問題（記録はハンターと独立）
- 図に印をつける：図をタップすると拡大ウィンドウが開き、ハンターモードと同じ方法（辺の印／角の印のどちらか一方を選び、その種類の要素だけに印。同じ印をもう一度で外す・消す・すべて消す）で印をつけられる。閉じる（×・閉じる・外側のタップ・Esc）と問題の図に反映。印は答え合わせに関係せず、カードの「すべてリセット」では消えない（「もう一度」で消える）
- あそびかたにパズル用のページを追加（タブで切りかえ）

### 証明パズルの解答レベル（Ver.0.4）

## 8. 技術構成

- HTML5 / CSS3 / JavaScript（ES2015程度、フレームワーク・ビルドなし）

- LocalStorage（キー：`proofHunter.v1`）
- Web Audio API（効果音）

各JSは `window.PH` 名前空間に機能を登録する。ES Modules を使っていないので、`index.html` をダブルクリックして `file://` で開いても動作する。
DOMに依存しないファイル（problems / geometry / validation / hints / storage / game / math-keypad / puzzle / rank-config / rank-questions / rank-game）は Node から `require` してテストできる。

## 10. 問題データの構造

`js/problems.js` の `PH.problems` に問題を1件ずつ書く。ハンターとパズルは**同じ問題ID・同じ正解データ**（`evidence`・`congruence`）を参照し、パズル専用には `puzzle`（形式とダミーカード）だけを持つ。判定・描画・ヒント・証明文はすべて共通処理がこのデータを参照するので、問題ごとの if 文は不要。配列はステージ順に並べ替えられる（同じステージ内は書いた順）。

```js
{
  id: 'p16',                     // 一意なID（URL #/play/p16、#/puzzle/play/p16 に使われる）
  number: '16',
  title: '〇〇を見つけろ！',
  difficulty: 2,                 // 1〜3
  stage: 5,                      // 所属ステージ（PH.STAGES の id）
  statement: '…であることを証明しよう。',
  given: ['AB＝DC', '∠ABC＝∠DCB'],  // 仮定（表示用）
  conclusion: '△ABC≡△DCB',      // triangles と同じ順番で書く（検証される）
  // 対応順に並べた2つの三角形（同じ位置の頂点どうしが対応）
  triangles: [['A', 'B', 'C'], ['D', 'C', 'B']],
  figure: {
    viewBox: [0, 0, 400, 400],
    points: { A: { x: 80, y: 60, label: [-16, -16] }, ... },  // label: 文字の位置（点からのずれ）
    lines: [['A', 'O', 'C']],    // 3点以上が一直線上に並ぶ線（角の同一性判定に必須。並び順も検証される）
    segments: ['AB', 'BC', { name: 'AC', hit: ['O', 'C'] }, ...],
                                 // 描画・選択できる辺。途中に点がある長い辺は hit でタップする部分を指定
    angles: ['ABC', ...],        // 選択できる角（真ん中が頂点、180°未満の角）
    parallel: [['A', 'D', 1], ['B', 'C', 1], ['A', 'B', 2], ['D', 'C', 2]],
                                 // 平行の矢印 [始点, 終点, 組番号]。同じ組は同じ向き。組番号の数だけ矢印を重ねる
  },
  reasons: ['given', 'common', 'vertical'],   // ハンターで表示する理由の選択肢（パズルの組み立てでは理由カードにも使う）
  evidence: [                    // 標準的な証明の順に並べる（証明文・穴埋めの行はこの順）
    { id: 'e1', items: ['AB', 'DC'], reason: 'given', label: 'AB＝DC', mark: 1 },
    { id: 'e2', items: ['∠ABC', '∠DCB'], reason: 'given', label: '∠ABC＝∠DCB', mark: 1 },
    { id: 'e3', items: ['BC', 'CB'], reason: 'common', label: 'BC＝CB', mark: 'common' },
    // 平行線の理由では parallelGroup（どの組の平行線か）と、証明文の書き方 proofReason を指定できる
    // { id: 'e2', items: ['∠BAC', '∠DCA'], reason: 'alternate', parallelGroup: 2,
    //   proofReason: 'AB∥DCより、平行線の錯角は等しいから', ... }
  ],
  extraTruths: [                 // 正しいが今回は使わない関係（その理由で答えたらミスにしない）
    { items: ['∠AOD', '∠BOC'], reason: 'vertical' },
  ],
  congruence: 'SAS',             // 'SSS' | 'SAS' | 'ASA'
  proof: { intro: '△ABCと△DCBにおいて' },
  // 証明パズル：形式とダミーカード（正解カードは evidence・congruence から自動で作る）
  puzzle: {
    type: 'build',               // Ver.0.3 の標準形式（参考情報。Ver.0.4 では解答レベルの選択が優先され、どの問題も3レベルで遊べる）
    distractors: {
      equations: ['AB＝AC', '∠ABC＝∠BAC'],   // ダミーの等式（図の上で等しくない／結論から導かれる関係だけ）
      reasons: ['vertical'],                  // 組み立てで追加するダミーの理由（PH.REASONS のキー、任意）
    },
  },
  hints: {                       // ハンター用：根拠IDごと＋'congruence' に3段階。focus は図で光らせる要素
    e1: [{ text: '…' }, { text: '…', focus: ['AB', 'DC'] }, { text: '…', focus: ['AB', 'DC'] }],
    ...
    congruence: sasHints('∠ABC', '辺ABと辺BC'),   // 共通文のヘルパー（sssHints / sasHints / asaHints）
  },
  explanation: '…',              // 完成画面の「今回のポイント」（両モード）
  learningPoints: ['…'],
}
```

結論が辺・角の等しさの問題（Ver.0.5）は、上に次を加える（`conclusion` は最終結論の表記になる）。

```js
{
  conclusion: 'AC＝BD',          // 最終結論（finalStep.label と同じ）
  conclusionType: 'equalSide',   // 'equalSide' | 'equalAngle'（省略時は 'triangleCongruence'）
  triangles: [['A', 'O', 'C'], ['B', 'O', 'D']],   // 途中で示す合同。正解の三角形と対応の唯一の基準
  // altTriangles: [[...], [...]], // 図の対称性などで、別の対応も正解にしたいときだけ（任意）
  figure: figureOf('p02'),       // 既存の問題の図をそのまま共有できる
  finalStep: {
    relationType: 'side',        // 'side' | 'angle'
    items: ['AC', 'BD'],         // 結論の2つ（頂点の対応順どおりに書く）
    reason: 'correspondingSides',// 'correspondingSides' | 'correspondingAngles'
    label: 'AC＝BD',
  },
  puzzle: {
    type: 'build',
    distractors: {
      equations: ['AC＝BD', ...],          // 根拠のダミー（結論を入れると「まだ根拠に使えない」の練習になる）
      reasons: [],
      triangles: ['AOC/DOB', 'AOC/OBD'],   // おてがるの三角形の組のダミー（対応ちがい・組ちがい。正解にならないことを検証）
      finals: ['∠OAC＝∠OBD', 'AC＝CO'],    // 最終結論のダミー（正しいが結論ではない関係／等しくない関係）
    },
  },
  hints: {
    triangleSelection: [ ... 3段階 ... ],  // 三角形を選ぶヒント
    e1: [...], e2: [...], e3: [...], congruence: [...],
    finalStep: [ ... 3段階 ... ],          // 最終結論のヒント
  },
}
```

- `proof.intro`（「△AOCと△BODにおいて」）は完成した証明で使う。STEP 1 の答えなので、問題文（`statement`）には証明する三角形を書かない。
- 理由 `correspondingSides`・`correspondingAngles`（`finalOnly: true`）は最終結論の段階だけで使う。根拠の段階の選択肢には出ない。
- 三角形の候補は図から自動で作る（`geometry.figureTriangles`：3辺がすべてかかれていて、一直線上にない3点）。図にかかれていない三角形は候補にならない。

ポイント：

- `items` の書き方：辺は `'AB'`、角は `'∠ABC'`。`AB`/`BA`、`∠ABC`/`∠CBA`、一直線上の別名（Oが AC 上なら `∠BAO`＝`∠BAC`）は自動で同一視される。
- 角の名前は必ず3文字。角は「頂点＋2本の半直線」で識別するので、一直線上に3点以上ある線は `figure.lines` に必ず書く。
- 「結論から導かれる関係」（対応する辺・角のうち根拠でないもの）は `triangles` から自動で判定されるので登録不要。ただし、結論を使わずに言える正しい関係（対頂角・錯角など）は `extraTruths` に登録して、ミスにならないようにする。
- ステージを追加する場合は `PH.STAGES` に `{ id, title, theme }` を追加する。
- 理由のID：`given`（仮定より）、`common`（共通な辺より）、`commonAngle`（共通な角より）、`vertical`（対頂角より）、`alternate`（平行線の錯角より）、`corresponding`（平行線の同位角より）。かっこ内はハンターの理由ボタンの文言で、証明文とパズルの理由カードでは「共通な辺だから」「対頂角は等しいから」などの標準的な書き方（`proof`）を使う。同じ要素を2つ選んだときは、`common`／`commonAngle` がハンターの選択肢に自動で追加される。新しい理由は `PH.REASONS` に `label`（選択肢）・`short`（スロット）・`proof`（証明文）を追加する。

### 証明パズルのカードの作り方（puzzle.js）

- **等式カード**（おてがる・スタンダード）：`evidence` の `label` と `puzzle.distractors.equations`。チャレンジでは等式カードを作らず、入力した等式を同じ形（要素キー・等式キー）に変換して判定する。同じ関係（左右の入れかえ・別表記）は1枚にまとめる。並び順は問題IDから決まる（毎回同じ）。
- **理由カード**（組み立てのみ）：各根拠の理由（`proofReason` があればその書き方）と、`reasons`・`distractors.reasons` の理由。根拠専用の書き方がある理由は、一般的な書き方を重ねて出さない。
- **合同条件カード**：3つの合同条件。
- **理由の判定**：理由のIDが同じなら正解。ただし根拠専用の書き方のカード（例「AD∥BCより、平行線の錯角は等しいから」）は、その書き方を使う根拠にだけ当てはまる（平行線が2組ある問題で、どちらの平行線かを区別する）。

### 問題・パズルの追加手順

1. 図の座標を、仮定と結論が成り立つように決める（2つの三角形は実際に合同に描く）。
2. 上の形式でデータを追加する（`puzzle` も忘れずに）。
3. `npm test` を実行する。`verifyAll` / `verifyProblem` が次を検出する。
   - 図にない・選択できない要素、理由が選択肢にない、ヒント・解説・ステージの不足、問題IDの重複、問題のないステージ
   - 結論の表記と `triangles` の対応順の不一致、つぶれた三角形、`lines` の点が一直線上にない
   - **図の座標で測ると等しくない根拠・`extraTruths`**、**図の2つの三角形が合同に描かれていない**、平行の印が平行でない
   - 根拠の組から導いた合同条件と `congruence` の不一致
   - **パズル**：`puzzle.type` が無効、**ダミーの等式が正しい関係（根拠・extraTruths）になっている**、ダミーが図の上で等しく見える（まぎらわしい）、未定義のダミーの理由
   - 角の操作領域どうしの重なり（`v02.test.js`）、全問題のパズルの判定（`v03.test.js`）
   - **Ver.0.5**：`conclusionType` が有効か、最終結論が途中の合同の対応する辺・角か（頂点の対応順どおりか・図の上で等しいか）、最終結論が根拠・仮定・`extraTruths` にふくまれていないか、`finalStep` の理由と種類、証明する三角形が図の上にあるか、三角形の組・最終結論のダミーが正解にならないか、`triangleSelection`・`finalStep` のヒント
4. ブラウザで実際に両モードをプレイし、タップのしやすさ・カードの分かりやすさを確認する。

## 11. 保存データの仕様

LocalStorage のキー `proofHunter.v1`（Ver.0.1・0.2 と同じキーで、そのまま引き継ぐ）。

```js
{
  version: 5,                    // Ver.0.2 で 2、Ver.0.3 で 3、Ver.0.4 で 4、Ver.0.6 で 5（古いデータは次の保存時に付く）
  problems: {                    // ハンターモードの記録（Ver.0.1〜、変更なし）
    p01: { cleared: true, bestStars: 3, minMisses: 0 },
    ...
  },
  puzzleProblems: {              // Ver.0.3 の証明パズルの記録（移行元。消さずに残す。Ver.0.4 では更新しない）
    p01: { cleared: true, bestStars: 2, minMisses: 1 },
    ...
  },
  puzzleLevels: {                // Ver.0.4〜：証明パズルの解答レベルごとの記録（ハンターとも、レベルどうしでも独立。★★★のときだけ下位レベルにも★★★を記録）
    easy:      { p01: { cleared: true, bestStars: 3, minMisses: 0 } },
    standard:  { p01: { cleared: true, bestStars: 2, minMisses: 1 } },
    challenge: {},
  },
  puzzleLevel: 'easy',           // 選んでいる解答レベル（初期値 easy）
  puzzleMigrated: true,          // Ver.0.3 の記録を移行ずみ（二重に移行しない）
  lastProblemId: 'p01',          // ハンターで最後に挑戦した問題
  lastPuzzleProblemId: 'p04',    // パズルで最後に挑戦した問題
  lastMode: 'puzzle',            // 「つづきから」のモード（Ver.0.2 以前のデータには無く、ハンターとして扱う）
  sound: true,                   // 効果音
  rankCertification: {           // Ver.0.6〜：段位認定（ハンター・パズルの記録とは独立）
    criteriaVersion: 1,          // 最高記録の認定基準のバージョン
    best: { rank: 13, rankName: '四段', effectiveScore: 13, correct: 15, maxCombo: 7, at: '…' },  // 認定時の段位名を保存
    bestCorrect: 15, bestEffectiveScore: 13, bestCombo: 7,
    playCount: 12,               // 最後まで終えた挑戦の回数（途中終了は数えない）
    lastResult: { correct, misses, passes, answered, effectiveScore, rank, rankName, maxCombo, criteriaVersion, completedAt, newRecord },
    lastReview: [ { no, qid, sourceId, typeLabel, question, yourAnswer, correctAnswer, explain, passed } ],  // 直近1回分の誤答（最大40件）
    previous: [ { criteriaVersion, best } ],   // 認定基準が変わる前の最高記録（比べずに残す。最大3件）
  }
}
```

- ステージのクリア数・★の合計・ステージクリア・復習対象は、保存せずに記録から毎回計算する（モードごと・パズルは解答レベルごと）。
- Ver.0.5 で保存形式は変わらない（`version` は 4 のまま）。新しい問題 p16〜p20 は記録がないので、未クリアとして始まる。既存の記録はそのまま。
- Ver.0.6 で `rankCertification` を追加（Ver.0.5 までのデータには無いので「未認定」から始まる。ハンター・パズルの記録は変わらない）。
  - 最高記録は同じ認定基準（`criteriaVersion`）の中で比べる。基準を変えたあとの最初の記録で、それまでの最高記録は `previous` に移して残す（過去の認定段位が設定変更で変わらない）。
  - 過去の全挑戦の履歴は保存しない（直近1回分の結果と誤答だけ）。個人情報は保存しない。壊れた値は「未認定」として読む。

### Ver.0.3 の記録の移行

- 読みこみ時に1回だけ、`puzzleProblems` のクリア済みの記録を、Ver.0.3 での形式に応じて移す：**穴埋め → おてがる、組み立て → スタンダード**。チャレンジはすべて未クリアから始まる。未クリアの記録は移さない（過去にプレイしていない形式をクリア済みにしない）。
- Ver.0.3 の形式は `storage.js` に固定した表（`V03_TYPES`）で判定する。`problems.js` の `puzzle.type` を後で変えても、過去の記録が別のレベルへ移ることはない。
- 移行ずみの印（`puzzleMigrated`）を保存するので、何度読みこんでも二重に移行しない。移行先にすでに記録があれば上書きしない。
- 元の `puzzleProblems` は消さない。ハンターの記録（`problems`）は変更しない。
- 復習対象：`cleared` が false、または `bestStars` が3未満の問題（★★★は対象外）。
- 壊れた値は安全な値（未クリア・★0・記録なし）として読む。過去のプレイ内容は推測で補わない。
- LocalStorage が使えない環境ではメモリ上だけで動作する（画面を閉じると消える）。

## 13. GitHub Pages公開方法

1. このフォルダをGitHubリポジトリにpushする（`index.html` がリポジトリ直下になるように）。
2. リポジトリの **Settings → Pages** を開く。
3. **Source** を「Deploy from a branch」、Branch を `main`、フォルダを `/ (root)` にして Save。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される。

ビルド工程は不要。相対パスのみを使っているので、サブパスでもそのまま動作する。

## 15. 既知の制約事項

### 両モード共通

- 各問題の証明ルートは1種類のみ。パズルのカードは登録した証明ルートの根拠と、正しい関係にならないダミーだけで作っているため、別ルートの正しい根拠がカードとして出ることはない。
- プレイ途中で画面を離れると途中経過は保存されない（クリア記録と最後に挑戦した問題のみ保存）。
- ステージクリアの演出は「全問クリアがそろった瞬間」だけ表示する。古いデータで既に全問クリア済みのステージは演出なしでクリア表示になる。
- 効果音はブラウザの自動再生制限により、最初の操作の後から鳴る。
- `∥` 記号はフォントによって `//` のように見えることがある。

### 段位認定モード（Ver.0.6）

- 認定基準は暫定版。ミニ問題は現在の20問の図から作るので、同じ図の問題がくり返し出ることがある（同じ問題は、未出題の候補があるうちは出さない）。
- 「対応する頂点」の問題の数が多いが、出題はカテゴリごとに均等にしているので、出題数は偏らない。
- 記号入力の問題は、等しい辺・角（A）、合同からの結論（E）、証明する三角形（F。5問）だけ。記号入力の割合（約60%）は、チャレンジゾーンの問題数が少ないと上下する。
- 途中で別の画面へ移ったとき（ブラウザの「戻る」など）は確認を出さずに挑戦を終え、記録しない（「やめる」ボタンでは確認する）。
- 時刻は端末の時計（`performance.now()`）で測る。端末をスリープしたときの扱いはブラウザによって異なるが、戻ったときに経過時間で判定する。
- 図を表示する問題でも、図の見た目（長さ・角度）では答えが決まらないように作っているが、図の上で等しく見える辺・角は避けきれない場合がある（正解は数学的な関係で判定する）。

### 合同から結論を導く問題（Ver.0.5）

- 証明する三角形の組と対応は、問題ごとに1通り（`triangles`。対称性などで別の対応を許すときは `altTriangles` に書く）。別の三角形の組で証明する方法は受け付けない。
- 三角形の候補は、3辺がすべて図にかかれている三角形だけ。現在の STAGE 6 の図は三角形が2つずつなので、ハンターの STEP 1 は「2つの三角形と頂点の対応」を答える形になる（おてがるのダミーは対応ちがいの組）。
- ハンターの STEP 1 では、1つ目の三角形の頂点はアルファベット順に並べ、2つ目の頂点を対応する順に選ぶ（1つ目の並びは自由に変えられないが、対応としては同じ）。
- 最終結論で「正しいが求められた結論ではない関係」は、ハンターではミスにせず、パズルでは誤ったカードとしてミスに数える（ハンターの「今回は使わない関係」・パズルのダミーと同じ扱い）。
- チャレンジでは、最終結論の等式の対応順の誤りはミスに数えない（根拠の等式と同じ）。三角形の対応の誤りはミスに数える。

### ハンターモード

- 別ルートで正しい根拠は、`extraTruths` に登録したものは「今回は使わない関係」としてミスにしない。登録していない正しい関係のうち、結論を使わないと言えないものは「結論から導かれる関係」または「まだ言えない」として扱う。
- 2段階の推論が必要な関係（例：p04 の ∠ABD＝∠ACD、p14 の ∠BDC＝∠CEB）は、1つの理由では言えないため不正解（「まだ言えないよ」）になる。
- 角は180°未満のみ対応。選択できる角は `figure.angles` に登録したもの（隣り合う2辺でできる角）に限られ、例えば問題01の ∠ABC（∠ABD＋∠DBC）は選べない。
- 途中に点がある長い辺（p14 の AB・AC）は、点より先の部分（D〜B、E〜C）をタップするとそのまま選ばれ、A〜D・A〜E の部分をタップすると「AB／AD」「AC／AE」のどちらかを選ぶポップアップが出る。DB・EC を単独の辺として選ぶことはできない（辺として登録していないため）。
- 現在の20問には、ふくむ角とふくまれる角を両方とも選べる図はない（重なった角のポップアップは、そのような図を追加したときに働く。テストでは例の図で確認している）。
- 交わる線の交点に名前がない場合（p04・p14）、交点のまわりの角は選べない。
- 印つけで生徒がつけた印と根拠の自動表示の印が同じ辺・角に重なる場合は、自動表示（緑）を優先して表示する（生徒の印は内部に残る）。
- 「ヒント」は最終段階を繰り返し表示できるが、回数は新しい段階を開いたときだけ増える（パズルも同じ）。

### 証明パズルモード

- 解答レベルは全問題共通の設定で、問題ごとに別のレベルを記憶することはしない。プレイ中にレベルを変えると、その問題は最初からやり直しになる。
- おてがる（穴埋め）では理由が表示済みのため、等式を入れかえられるのは「同じ理由の行どうし」だけ（例：p01 の ① AB＝CB と ② AD＝CD）。理由の違う行に入れると、その理由では言えない等式として不正解になる。
- ダミーの等式は問題ごとに手で指定している（自動生成はしない）。ダミーには「図の上で等しくない関係」と「結論から導かれる関係」だけを使い、`npm test` で確認している。
- 理由カードの文言は証明文の書き方（「対頂角は等しいから」など）で、ハンターの理由ボタン（「対頂角より」など）とは表記が異なる。
- 完成画面の証明文の行の順番は、生徒が組み立てた順になる（標準の順と異なることがある）。
- チャレンジでは、入力した等式が登録した証明ルートの根拠と同じ関係かで判定する（別ルートの正しい関係は、`extraTruths` に登録したものも含めて不正解になる）。図にかかれていない線分（例：p01 の AC）や、一直線上で角にならない入力（例：∠OAC で O・C が A から同じ向き）は、エラーにはならず不正解として扱う。
- チャレンジの等式欄は、辺か角かを生徒が選ぶ（どちらの等式が入るかは表示しない）。∠ は「角の等式」を選ぶと自動で入る。
- 入力途中の等式は、その問題を解いている間だけ残る（画面を離れると消える）。
- Ver.0.3 の記録の移行は、クリア済みの記録だけを対象にする。
- 図につけた印は、その問題を解いている間だけ残る（画面を離れる・「もう一度」で消える。保存はしない）。完成画面の図には、根拠の印（自動表示）だけを表示する。
